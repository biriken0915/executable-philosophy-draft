# 付録B — 用語集・思想家索引

本書の語彙は、哲学用語と設計語彙が同一の層で混ざっている——それは混雑ではなく設計である（→序章：三つ組の方法）。本付録は二つの索引を持つ。**B.1 用語集**は、本書が設計語彙として使う語（★=初出節）を、定義・該当節・対応する設計実体付きで列挙する。**B.2 思想家索引**は、本書が参照した思想家を、中心概念・出現節・本書がその概念から抽出した「設計命令」の形で列挙する。索引の使い方は→終章の継承の回路の語で言えば、**引用の追跡可能性**である——読者が本書の任意の設計を、その哲学的供給源まで逆に辿れることが、本書の主張の検収可能性の一部である。

## B.1 用語集

**アポリア（aporia）★終章・各章末**：問いの進み方が止まる地点。本書では解決待ちの残件ではなく、OPEN-PERMANENT で登記し監視する対象（Aporia ノ節参照・終章）。設計実体：Aporia 台帳＋decay_query。
**ACL（防腐層）★6.1**：隣接系の語彙が自系に漏れるのを防ぎ、翻訳を条約として記録する層（Evans の DDD 由来、→6.1）。設計実体：TermMapping・TranslationFailure・Quarantine。
**障礙（obstacle）★3.4**：目標の論理的否定の形で表現された障害（Lamsweerde の KAOS 由来）。障礙台帳は「今何が分かっていないか」の目録。設計実体：Obstacle ノード・NEGATES 辺・N2 辺。
**器（instrument）→各章**：判断の条件を実装する機械的部分品の総称。四器＝皿（候補提示）・制約（門と形状）・時間（予算と落日）・不服従（ dissent の通路）。
**確証（warrant）→4.3・5.1**：主張が根拠によって支持されている状態の、記録可能な形。証明ではなく水準（E1〜E4 級、→4.1）として扱う。
**共同化（socialization）★8.3**：SECI の tacit→tacit 環（→8.3）。形式化できないが場の設計はできる、が本書の設計命令。設計実体：CoproSession・Viewpoint・COEXISTS_WITH。
**共観（copresence）★8.3**：同一の状況を同一時間に共に閲覧する設計。同時性・見解併置・沈黙の保持の三条件。
**勘定（reckoning）★5.1**：規則に則った計算による出力（Cantwell Smith の reckoning）。正しくても根拠・責任・更新経路を含まない（→5.1 の三段分割）。
**形式化の残余（hjelmetane、helmetanaiya）★1.2**：どんな形式化にも必ず溢出すること（ヘルメタネア）。消去でなく記録の対象。設計実体：TranslationFailure・Quarantine・残余条項。
**権限の弁（rollout gate）→7.6**：read-only→propose→act の段階的権限委譲。昇格は人間・降格は数値の非対称原則。
**系譜（genealogy）→2.6**：ある語・規則・機構がどの条約から生まれどの審議を通ったかの履歴参照。commit message の link に相当。
**現前化（making-present）→5.2**：過去の知識・経験を現在の判断材料として立ち現らせる作用（ハイデガーの Zeitigung の読替）。更新経路なき fluent な現前化は消費、→5.2。
**四器の分離→序章・A.1**：皿・制約・時間・不服従を単一部品に溶融させないアーキテクチャ命令（→5.3 司令塔化の防壁）。
**実効的承認★5.1**：根拠が実際に再検証可能で、判断者の更新経路を含む承認。署名のみ・皿の内側のクリックは「実効的承認」ではない。設計実体：JudgmentEvent + basis_reckoning + revalidation_path + update_route。
**新語生成（coin-term）→7.1**：現場が状況語彙を新設する行為（規則の生成）。知の所有権の指標（→8.1 の計器）。
**深層の簿記（provenance bookkeeping）→5.4**：LLM 呼び出しの環境（model_ref・temperature・seed・sys_prompt 版数）を Candidate に刻む設計。再現性の物理的条件。
**人工的沈黙→2.6・6.4**：変更の告知後の保留期間。沈黙は同意ではない（→8.5）が、保留の設計によって沈黙の意味が確定する。
**申告（declaration）→3.5・4.1**：UNKNOWN・残余・地平の有効期限を、宣言データとして登記する形式。UNKNOWN を隠さない三段構え。
**審議槽（deliberation slot）→2.6・6.2**：意味変更・例外・不服従が載せられる議席のデータ構造。載せる・空けない・解決率の三計器（→6.6）。
**振る舞い仕様（behavior spec）→1.5**：宣言（API・規則・契約）と実体（実コード・実挙動）の突合。CI での版数検査。設計実体：stale-spec 検査（→7.5）。
**落日条項（sunset）★6.6**：規則・宣言・境界・権限に自動的に死期を設定し、延命には実測根拠の再承認を要する設計。腐敗速度 > 発見速度への構造的回答。
**妥当性要求（validity claims）★6.2**：コミュニケーションが暗黙に提起する四要求（理解可能・真・正統・誠実、ハーバーマス）。四要求=四つの機械検証可能ゲートの設計図（→6.5）。
**判断（judgment）★5.1**：コミットメント＋責任末端＋更新経路を伴う引受（Cantwell Smith の judgment）。本書の不変条件四の主題。
**止揚（Aufheben）★2.2**：否定された段階の真理を保存しつつ次段へ移す運動（ヘーゲル）。差分・履歴・supersessionBy の設計として読替。
**命令なき編成★7.4**：メッセージ語彙に order を持たず、候補・判定・判断・反証の差し出しだけで構成されるマルチエージェント（→7.4 Exchange）。
**委任深度（delegation depth）★7.2**：現場が規則を選定できる範囲の等級（→4.1 級・→7.1 phronesis 残高）。深度は時間予算と実測で決まる。
**目的因（telos）★3.1**：何のために、の原因（アリストテレス四原因説）。要件定義の欠落器官として復権させる。設計実体：Goal.intent・Why の条約。
**門（gate）★6.4**：allow/deny の決定論的判定を、理由（missing）付きで出す独立部品。default-deny・plan/execute 二段・decision log。
**形状（shape）★6.5**：グラフの部分構造に対する妥当性制約（SHACL）。門（意図）と形状（構造）の二重検証（→6.5 の 6.5.2）。
**時間優勢（time advantage）★7.2**：判断周期の短さによる優位（ボイド）。時間予算=SLA・周期の階層・段予算の実装対象（→7.5）。
**増幅化（amplification）★8.4**：人間の行為の質・速さ・射程を伸ばす配線。自動化（代行）との対概念。判別試験=人間の出力が規則（憲法）へ流るか否か。
**見せかけ承認→5.1・5.3**：根拠の再検証経路を持たない署名。尤度の物語化と laundering（正統の洗浄）の連鎖を生む。
**尤度の物語化★5.3**：尤度（それらしさ）を真理性・存在・正当性と取り違えて語りにする作用。E4 宣言・反証条件の不在がこれを許す。
**歴史代数★2.5**：知識の変更を可換図式・差分・supersessionBy で記録する代数。git→RDF ブリッジ（→2.5）。
**不服従（dissent）★6.2**：方針への反対の正式登記。登録と審議槽の自動起案が必須。不服従の通数量は健康指標（→6.6）。
**不変条件（invariant）→5.6・終章**：常に真であるべき述語。テストで機械検査される。四元素不変条件（→5.6）、五不変条件（→終章）。
**瓶（bottleneck）→2.4 練習**：境界語彙の翻訳が審議のボトルネックとなる現象。条約貿易の摩擦計測の対象。
**被投性（geworfenheit）★5.2**：既に投げ込まれた状況からしか出発しないこと（ハイデガー）。前提の宣言（E4）の必然性の根拠（→4.1 の設計転化）。
**プロテタリア化→8.1**：労働から労働の知的内容が剥奪される過程（スティグレール）。三計器（site_coinations・frame_conformity・stale_obstacles）で測る。
**弗雷ゲ的切断の否認→1.6・2.6**：価値と事実、記述と規範、意味と機構の分離を完成しないこと。記録しないこと・不服従・落日が「切断の埋め戻し」機構として設計される。
**予測不可能性の設計→3.4**：障礙・残余・UNKNOWN など、予測できないものが入る口を先に設計する姿勢（→3.5 の地平の宣言）。
**皿（frame）★5.3**：判断者に提示される選択肢・根拠・地平の総体。皿の作り手（frame-maker）の権力が、LLM 実装で最も危険な位置（→6.3 の frame_options）。
**知識議席★2.6**：知の条約（TermMapping・規則・例外）の審議に参加する権利の席。知の所有権の第一条約（→8.2）。
**観測者効果の設計→8.3**：測られる行為は測られる用に変わる（→6.6 の指標の武器化）ため、測る範囲・避難所・読み方（系で読み個人で読まない条約G-1）を設計する。

## B.2 思想家索引

各項目は、中心概念／本書での出現節／本書が抽出した設計命令、の順。

**アリストテレス（Aristoteles, 前384-前322）**：四原因説と目的因（→3.1）、デロクシス／実践知（→7.1）、エピエイケイア＝衡石の曲げ（→6.6 引用）、德性の習熟説（→終章）。抽出命令：目的は原因としてデータ化される（telos→Goal.intent）。德性は行為の反復でしか維持されない（drill・更新経路）。
**ウィトゲンシュタイン（Wittgenstein, 1889-1951）**：論理哲学論考の画像説と検証原理の破綻（→4.5）。抽出命令：世界と命題の同型性を要求する形式化は、自己の適用不能を証明して崩れる——よって契約と宣言で足りる（→4.4）。
**ヘーゲル（Hegel, 1770-1831)**：止揚・規定された否定（→2.2）。抽出命令：知識の進歩は差分と supersessionBy で記録され、廃棄段階の真理が保存される。
**ハイデガー（Heidegger, 1889-1976）**：手持ち性/現前性、故障（→5.2）、被投性（→5.2・4.1）、時間性＝現前化（→5.2）。抽出命令：故障は三型に分かれ、型ごとに提示と記録が違う（breakdown ledger）。前提は隠すものではなく宣言するもの。
**西田幾多郎（1870-1945）**：場所の論理・絶対無（→1.3、純粋経験）。抽出命令：関係は実体より先在でありうる——グラフの辺がノードより先に意味を作る（→1.3 の設計）。
**ポランニー（Polanyi, 1891-1976）**：暗黙知・補助覚知（→1.1・1.2）。抽出命令：可言明な知は暗黙知の地面からしか生えない——形式化は地面を保存しないため、場の設計が要る（→8.3）。
**ボイド（Boyd, 1927-2006）**：OODA ループ・時間優勢・本質のミーム（→7.2）。抽出命令：周期は階層・時間予算は仕様・本質定義の注入がオントロジー汚染。
**ランスウェルデ（van Lamsweerde, 1956-）**：KAOS・ゴール木・障礙（→3.4）。抽出命令：障礙は目標の否定として形式化される（N2 辺）。
**野中郁次郎（1935-）**：SECI・場（ba）の理論（→1.3・8.3）。抽出命令：共同化は形式化できないが、共観・避難所・drill で場を設計できる。
**ハーバーマス（Habermas, 1929-）**：討議倫理・四妥当性要求（→6.2）。抽出命令：四要求は四ゲートの設計図——誠実性だけは検証不能なので登記のみ。
**エヴァンス（Evans, 1973-）**：DDD・防腐層・デュアルバウンダリ（→6.1・6.3）。抽出命令：防腐層は壁でなく条約で、条約には貿易統計と双方向検証が要る。
**スティグレール（Stiegler, 1952-2020）**：第三次保持（→2.3）、プロレタリア化（→8.1）、個別化・教育（→8.2）。抽出命令：外部化された知識は理解なき操作を許す方向へ滑る——滑りを止める配線（四配線・共観・drill）を設計に内蔵せよ。
**キャントレル・スミス（Cantwell Smith, 1951-）**：Reckoning vs. Judgment（→5.1・5.3）。抽出命令：意味ある出力は根拠・責任・更新経路を必要とし、判定函数はそれらを出力しない。
**ミッション・コマンド（米国海兵隊教義）**：意図ベース指揮（→7.2）。抽出命令：委任は制約＋障礙＋時間予算で渡す——目的の細部命令は渡さない。

索引の末に、本書の方法の索引を一つ添えておく。これらの思想家の選び方は**網羅ではなく配管**である——本書は、設計命令へ抽出可能な概念を持った思想家だけを、必要な章に配置した（→4.5 の「物語化」への自己防衛：思想家の引用が飾りになった瞬間、それは尤度の物語化である、→5.3）。読者はこの索引で、各設計命令の供給源を原典まで辿れる——辿って、抽出の誇張と縮小を判定されたい。**その判定が、本書の最後の実行練習である。**

### 実行練習

1. 用語集の三項目（実効的承認・落日条項・審議槽）について、あなたの組織の対応物（ある/ない/名ばかり）を判定し、名ばかりの項目に「執行機構」を1つずつ設計せよ（→6.4 の IMPLEMENTED_BY 双方向監査の語で、名ばかり=grant without enforcement）。
2. 思想家索引から1人選び（未読の者を選ぶことを推奨）、本書の「抽出命令」が原典の誤読でないかを1時間調べて判定せよ。誤読・誇張を見つけた場合、それを本書の Objection 型（→8.4）で登記する練習を本気で行え——本書への反論は、本書の回路に通すのが正しい反論の形である。
