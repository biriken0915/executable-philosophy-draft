# 序章 — なぜ「実行可能な」哲学書なのか

## 読んだ瞬間に分かってしまった、という嘘

哲学書には、読んだ瞬間に「分かった」気がする体験が付きまとっている。カントを読み終えた夜、世界が少し整って見える。ハイデガーの「現前性」の章を閉じたあと、道具の壊れ方が以前より鮮明に見える。その感覚は嘘ではない。だが本書は、その感覚の**続き**を問うてやまない。翌朝、あなたの現場で機械が異常振動を始めたとき、カントは動いたか。ハイデガーは、その振動を記録台帳のどの語に載せたか。壊れた承認フローのどの段に、ウィトゲンシュタインは割り込んだか。

答えは普通、「哲学はそういうものではない」である。確かにその通りで、哲学はツールではなく、現場の問題を即座に解く道具箱でもない。本書は哲学を道具箱へ降格させる本ではない。本書が主張するのは、むしろ逆向きである——**哲学の主張の多くは、実行可能な形を与えられたときに限り、初めて検証可能になる**。ハイデガーは「道具が壊れると存在者として立ち現れる」と主張した（→後の 5.2 で本格的に扱う）。これは深い観察であると同時に、実装可能な仕様の断片でもある——壊れ方の分類を作り、分類ごとの提示設計を決め、壊れたものが記録に載る回路を作れば、この主張は**走る**。走ったとき、我々は初めて、この主張がどこまで真で、どこから嘘になるかを知ることができる。哲学の主張を、走る主張と、永遠に走らない主張とに振り分ける作業——本書はそれを、21世紀の技術（グラフデータベース・記述論理・ポリシーエンジン・LLM・ステートマシン）を使って実行する。

もう一人の証人を出す。アリストテレスは『ニコマコス倫理学』で、学ぶ者は「聞くだけでは足りず、実際にやって学ぶ」と書いた——建築は建築によって learn される、琴は琴によって。倫理の知（フロネシス）は、命題の所有ではなく行為の性質である、と。この一文を文字通りに取ると、面白い帰結が来る。**判断の哲学を本当に学ぶには、判断が走る機械が必要である。** 判断を模し、判断を検証し、判断の履歴を積む機械——その機械の設計図を読むことは、判断についての哲学を読むことと同一の作業の、もう一方の形態である。本書は、その同一性を賭けた実験である。

## 形式化は判断の代行ではない

本書の中心命題を、序章の冒頭に宣言として置く。あとで撤回するために置くのではない。全書七章分の一歩一歩で、この命題の意味を精密にしていくために置く。

> **形式化とは、判断を機械に委ねることではなく、判断の条件を機械に渡す作業である。**

この一文は、通常の自動化プロジェクトの自己理解の**正反対**である。通常の理解では、自動化とは「人がやっていた判断を機械がやるようになること」である——機械学習モデルが分類し、ルールエンジンが承認し、ワークフローが裁く。本書はこの理解を、序章から終章まで一貫して拒否する。拒否の理由は道徳的ではない。**構造的**である。判断とは、根拠・責任・更新経路を持つ行為であり（→5.1 で定義する）、これら三つのいずれもが、判定函数の出力には含まれない（→3.6 で「判断の非封閉性」として証明的に示す）。判定函数に判断を「委ねた」瞬間、根拠・責任・更新経路は宙に浮く——宙に浮いたそれらは消滅せず、誰かの暗黙の補完、記録されない例外処理、不在の責任として、系の**裏側**に残る。本書はこれらの裏側の残骸を、第5章で「隠れ判断」「尤度の物語化」「責任の蒸発」と名づける。

形式化の正しい理解——判断の**条件**を渡す——の意味を、ここで一度だけ先取りしておく。機械に渡せるものは三つある。第一に、**状況の構造**（何が起きているかの型・語彙・関係——グラフと記述論理が担う、→1.3）。第二に、**制約の名簿**（何が許されないか・何が未決か——ポリシー・形状・不変条件が担う、→6.4〜6.5）。第三に、**時間と手続**（いつまでに誰が応じるか、不服従はどのパスを通るか——ステートマシンと監査が担う、→5.5・6.4）。機械に渡せないものは一つある——**コミットメント**（この状況で、私はこうする、と引受手続に署名し、その責任の末端になる行為）である。形式化の仕事は、コミットメントを機械化することではなく、コミットメントが**正しく下される条件**——正しい皿・正しい根拠・正しい時間・正しい不服従——を機械に実装することである。本書の全コードは、この四つの「正しい」の部分実装の集積として読める。

宣言を、本書の形式に則って宣言自体のデータ化で始める（→2.5・4.1 で本格化する「宣言もデータ」の原則の、序章における自己適用）。

```cypher
// book-charter — 本書の中心命題を、本書の語彙で登記する(自己言及の開始)
CREATE (t:Treatise {title: '動く哲学書',
        thesis: '形式化は判断の代行ではなく、判断の条件を機械に渡す作業である',
        declared_by: 'author', declared_at: datetime(),
        -- 宣言は検証可能性を含む(→4.1 で this は E1/E4 級の話になる):
        -- 本書の各設計が『判断の条件』を渡していないと証明された節で、
        -- この命題は falsified として登記される。その falsification 用の照会:
        revalidation_path: 'MATCH (d:DesignDecision)-[:SERVES]->(m:Treatise) '
                         + 'WHERE NOT (d)-[:CONDITIONS]->(:JudgmentSlot) RETURN d'};
```

この三行の照会が序章の全体であるとも言える。本書は、中心命題が falsified になる条件を、最初のコードとして書く。この形式——**主張は、その反証条件と同居する**——が序章から終章まで一貫する。4.2 で「反証可能な CQ」として定式化され、8.5 で「反証条件の必須添付」として UI になる。

## 本書の地図 — 五部・八章の階段

本書の構成を、一問一答の階段として示す（各部の章は、前の章の答えを次の章の問いに変える設計になっている）。

**第一部 構造（第1〜2章）**。問い：状況は機械に理解できるか。第1章は状況・暗黙知・残余（ヘルメタネア）の概念をグラフと記述論理で実装し、機械の「分かる」の限界を測る。第2章は知識が合意・変更・権力で動く過程を、git 型の履歴代数と承認モデルで RDF に写し、意味の政治を記録可能にする。
**第二部 目的（第3〜4章）**。問い：目的は機械に検収できるか。第3章はゴール木・形式仕様・障礙（目標の否定）で目的構造を作り、4.5 の「目的は閉じない」定理でその限界を確定する。第4章は契約（DbC・CQ・反証可能性）で目的を引受可能にする。
**第三部 判断（第5章）**。問い：reckoning（勘定）と judgment（判断）はどこで分かれ、どこで人を責めるのか。尤度と正当性とコミットメントの三層分割と、ステートマシンによる「世界を変える権限」の設計がここにある。
**第四部 防腐（第6章）**。問い：意味の腐敗を、誰が、どの配線で止めるのか。境界・条約・門（Rego）・形状（SHACL）・不服従・落日条項——体系の自己防衛の免疫系。
**第五部 実行と人間（第7〜8章）**。問い：この体系は動き、そして人間は何になるのか。第7章は実践知・委任・行動グラフ・LangGraph・実線パイプラインで全体系を走らせる。第8章はそこで人間から奪われるもの（プロレタリア化）を自己批判し、知の所有権・共観・共創・再身体化の配線で取り戻す。

地図の読み方を一つ注ぐ。この階段は**一方向ではない**。第5部の自己批判（8.1）は第1部の前提（1.3 の形式化の約束）へ跳ね返り、第4部の落日条項（6.6）は第3部の承認制度（3.6）へ跳ね返る。本書の交叉参照（「→x.y」の形式）は、この跳ね返りの通路である。交叉参照を辿って読むと、本書は環になる——哲学書の環状構造を、あえて文書の物理的な参照で実装してある。

## 読み方 — 三つ組のリズム、実行練習、コード

本書の各節は同じリズムで書かれている——**思想・工学・コードの三つ組**。思想の節（各章の第1〜2節が主）は哲学者の中心概念を、必ず「では設計で何を強制するか」まで運ぶ。工学の節（第3〜4節）は概念を設計機構（ノード・条約・門・状態機械）に翻訳し、翻訳で失われるものを正直に書く。コードの節（第5〜6節）は機構を動く形（実行可能な形式）で置き、テストで検収する。このリズムは飾りではない——三つ組は、本書の方法（→前掲の命題）の三局面である。思想が条件の発見、工学が条件の実装設計、コードが条件の検証可能形態。

**コードの約束**。本書のコードは「イメージ図」ではない——実行可能な形式で書く。実行可能な形式とは、(a) 言語指定つきのブロック（```` ```python ```` 等）、(b) 依存環境は付録A（Neo4j 5.x / Python 3.11 / Pydantic v2 / z3-solver / OPA / pySHACL / LangGraph / FastAPI の docker-compose 環境で動作）、(c) 本文で参照する識別子は本書内の他のコードで定義済み、の三条件を満たす。すべてのコードが全書を通じて一つの体系に接続される——第1章のグラフスキーマに第7章の実線が発火し、第2章の履歴代数に第6章の落日条項が載る。したがって本書のコードは章を跨いで読む価値がある——**最後のデモ（7.6）が動くとき、それは哲学書の全章が CI で走ったことを意味する**。読者がコードを実行する気にならない場合でも、コードは読むべきである——本書でコードは、哲学的主張の**検収書**として機能している。検収書の読み方（何が test され、何が test されていないか）が、本書の主張の正確な輪郭になる。

**実行練習**。各節の末尾に三問の実行練習を置く。三問の設計原則は固定的で、第一問は**移植**（あなたの領域に翻訳せよ）、第二問は**診断**（あなたの現在の系を本書の計器で測れ）、第三問は**条約**（設計の代償を宣言・等級・落日の形式で明示せよ）。練習は読後オプションではない。本書の中心命題——形式化は判断の条件を渡す作業——が正しいなら、あなたの判断の条件をあなたが設計し直さない限り、本書は読めていないことになる。練習を飛ばした読者は、本書を**読んだ**ことにはなるが、本書が走る現場は一つも増えていない。その差が、この本の全内容である。

最後に、この本の読者への想定を正直に書く。読者は、設計者でも開発者でも管理者でもあってよい。ただし三つのうちの二つ——(1) 何かを設計したことがある（フローでも制度でも）、(2) 何かを壊した経験がある（運用事故・要件の化け方）——を満たすことを要求する。満足しない読者はいない。本書の第3.4節が言う「障礙」（目標の否定の形での障害の理解）を、あなたはもう知っている。知らないのは、その知っていることの設計語彙だけである。

## この本が応答する三つの懐疑 — 先に名乗らせてもらう反対

読者が本書を手に取る前に持っているだろう三つの懐疑を、先に引用し、先に名乗る。反論を前置きに入れるのは弁明のためではなく、**反論そのものが本書の障害分析**（→3.4）だからである——本は読者Beforeに障礙台帳を見せるべきだ、という要求工学の作法にしたがう。

**懐疑一「哲学は美しいが、現場を一つも変えたことがない」**。半分正しい。哲学は単独では現場を変えない——分類制定の級（→2.6）も落日条項（→6.6）も、哲学書が書いたものではなく、哲学を**設計語彙に翻訳した工学者**が書いた。本書は翻訳の作業記録である。翻訳は必ず摩擦を残す（→6.1 の条約と摩擦統計）——だから本書は各概念の翻訳残高（「何が削れたか」）を明記する。翻訳残高を明記しない哲学の利用は、懐疑一を再生産するだけである。
**懐疑二「現場は哲学を語る時間がない。速い系統に遅い讲釈はいらない」**。本書の三部（→5–7 章）はこの懐疑のためにある——5 章のステートマシンは速い系統のための機構、6 章の防腐層は遅い讲釈を門の外で済ませる配線、7 章の委任は「讲釈の時間がない」現場に**判断の席を置く**設計（→7.2 の時間予算 decision_budget_sec は、懐疑二を SLA に化かしたものだ——哲学を讲釈する時間がないなら、哲学を**配線**する）。7 章を読み終えた読者は、懐疑二が速度ではなく配列の問題だったことに気付く。
**懐疑三「AI が全部やる時代に、人間の判断を拠えるのは時代錯誤だ」**。本書の答えは 5 章と 8 章の二段構え——5 章は「AI に判断を載せる機構が存在しないこと」の技術証明（確率に末端は書けない、→5.3）で、8 章は「判断を人間に拠えた系統ですら知を空洞化する」ことの実装自戒（→8.1 の deskilling-meter、本書 own pipeline への）。懐疑三の最も誠実な形——「お前たちの設計ですら空洞化するだろう」——に本書は第八章で先に同意し、計器を渡す。時代錯誤かどうかの判定は、読者の四半期後の site_coinations（→8.1）が見せる。

三つの懐疑への答えを一文ずつに凝缩しておく。**翻訳残高を載せよ（一）。哲学を讲釈せず配線せよ（二）。空洞化の計器を自らに差し向けよ（三）。**本書の全体は、この三文の実装目録として読める。

## 用語の訳語について — 最小の断り書き

翻訳摩擦の最小の例として、本書の訳語规約を四行だけ断っておく。哲学専名は日本語定訳を使うが、**設計語彙に化ける際は原語を併記する**（Aufheben・third retention・individuation は原語で覚える——概念がコードの語と結婚するからである。クラス名 Cypher の関係名が原語由来の英語なのは、そのためだ）。独逸哲学の「Vorhandenheit/ Zuhandenheit」は現前性/手持ち性（定訳）を使うが、5 章では現前化の**作用**（Zeitigung・時化）に着重する——存在論の状態語を、更新経路の動作語に読み替えるためである。ヘーゲル的「Aufhebung/止揚」は本書で「差分として計算可能な保存」に読み替えられ（→2.2）、この読み替え自体が E4 宣言（→4.1 の級つき前提）として登記される——**本書の全訳語は、訳した者の責任として級を負う**（→2.6 の分類制定の級が、書籍の内部でも适用される）。これが「動く哲学書」の形式上の意味の一つ——引用の権威ではなく、訳の責任で立つ書物である。

## この本が何でないか — 三つの境界画定

何であるかの前に、何でないかを三つ画定する（境界を引かない書物は読者に境界を引かせる——2 章の分類の暴力が読書の読み込みでも起きるため、著者側で先に引いておく）。

**其一、哲学史の教科書ではない**。カントからハイデガーへの系谱、アリストテレス四因の学説史、ヘーゲル研究の当代の論争——これらは本書では**設計語汇として使える形に削れて**現れる（削れ方の明細=翻訳残高は各章に載り、思想家索引=附録B.2が「本書が何を読んだふりをしているか」の照会にもなる）。哲学史を正しく語る書物はいくらでもある。本書は哲学を**道具として誤用する書物**であり、その誤用の自覚（誤用した場所に級を載せる、→preface 終near の術語責任）が唯一の免状である。
**其二、方法論書ではない**。本書に「始め方」はある（終章の九十日計画）が、方法として普遍化できるものはない——各章の機制（CQ・落日・級・席）は特定の正规系（Neo4j・OPA・SHACL・LangGraph）に落とされた**実装例**で、方法論として書き直せば中身が空になる（方法論が空になる理由本身が本書の主題——形式化は判断の代行ではない、方法にすれば代行した気になる）。読者が自分の技術スタックに載せ替える際、本書の代码は写せない——写せるのは代码が書かれた**質問の形**だけである。
**其三、解決書ではない**。本書の機構は障礙を消さない——障礙を簿記し、席に載せ、落日させる（3 章の障礙台帳が「消えた障礙」を永遠に報告できない構造であるように、本書も自分の産出を「解決」と呼ばない）。解決を約う書物の落日は出版日に始まるが、本書の落日は出版日から 18 か月後に書いてある（終章の書物自身の落日条項）。

三つの境界画定の末尾に、本書が唯一約うものを一行置く——**本書は世界を直さない。世界を記述する語の台帳を、直すことのできる形に保つ**。台帳が直す方向を向くのは、次の四半期の会議の席で、誰かがその台帳を読み上げ、決定に署名する時である。その席の設計が本書の全編である。

### 本書のコードの読み方 — 壊れたコードの約束

本書のコードブロックは三種ある。**其一、動くためのコード**（schema.cypher・gatekeeper.rego・z3_gate.py など）——リポジトリの対応ファイルと同一で、そのまま走らせられる形に保つ（走らせない場合、あなたの技術スタックに載せ替える際の質問の形として読む）。**其二、動くはずの見本**（章内で折々現れる断片）——文脈を省いて載せるため、単体では import も含めない。この種類には冒頭に断片の範囲をコメントで書く。**其三、**故意に壊してあるコード**（附録A.3 に明記した 1 本を含む）**——壊れた代码は壊れた世界を記述する。書物の代码が全部動く時、書物は世界の障礙を假定していない（障礙モデルなしの健全系は 3 章の中心の不在）。壊してある場所は必ず注釈で示す——**壊し方が隠れていればそれは缺陷で、示されていれば設計である**（本書の壊し方の原則：壊れた代码は落ちる場所が确定で、落ちた時の届け出先が代码内に書いてある——コード内の comment の矢印「→x.x 節」が全書を贯る交叉参照網络であり、代码は哲学の脚注ではなく哲学の呼び出し元である）。

交叉参照の約定もここで一環する。「→x.x 節」は前後方向を結ぶ（第1章で導入した概念が第8章で計器になり、第8章の計器の前提が第2章の台帳になる）。本書に周回（サイクル）はない——各章は独立に読めるが、各章は独立に**正しくはない**（1 章なしの 5 章は技術書、5 章なしの 8 章は叹き、8 章なしの 1 章は知識論の讲釈）。読む順序は自由、構成は五部（→preface「本書の地図」）、そして最後に読むべきは終章の落日条項である——書き手がこの書にいつ死 period を設けたかを先に知っておくと、各節の言い切りの強さが読み違えられる（落日のある書物の言い切りは、永遠の真理でなく期限つきの判断として読む——本書の読み方そのものが、本書の中心命題「形式化は判断の代行ではない」の読書実践である）。

### 実行練習

1. この序章の中心命題（形式化は判断の条件を渡す作業）を、あなたの現在の主要な自動化・制度の設計に当てはめて書き換えよ（「X の形式化は、Y の条件を Z に渡す作業である」の形に埋め、X/Y/Z をあなたの語で埋めよ）。埋まらない場合、あなたの automation が「判断の代行」になっている場所を1箇所特定し、本書の語彙で名前を付けよ（後の章で診断語彙は手に入る——まず仮の名前でよい）。
2. `book-charter` の照会を、自分の信条1つに対して書き換えよ（あなたの設計信条・中心仮説を `thesis` に置き、その revalidation_path=反証照会を1本書け）。反証照会が書けない信条は、本書の語で言えば宣言ではない——宣言のふりをした信念である。その区別が本書全体で作動する（→4.1・5.1）。
3. 本書の五部の地図を写し、五段階それぞれで「あなたの現場の現在位置」に△を付けよ（構造はグラフで語れるか、目的は検収可能か、判断と勘定は区別されているか、腐敗の免疫はあるか、人間は何になっているか）。最低の△が、あなたの最初の一章である——その章から読み始めてよい。逆に、最高だと思う△の章を先に読み、その章の「失敗の目録」小節で自分の現場を測り返す読み方も有効である（→4.6・8.1 の計器が先に欲しい読者向け）。
