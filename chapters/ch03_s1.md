## 3.1 アリストテレスの四原因説と目的因（telos）の復権

第1部が「知とは何か」を問う存在論・認識論だったのに対し、第2部から本書は問いの方向を変える。「このシステムは**何のために**存在し、そのために知っていることは**十分か**」——十分性の問いである。この問いを近代科学は失くした、とよく言われる。正確に言えば、失くしたのは世界の説明から目的を排除したことではなく、目的を**形式化不能な残り物**として追放したことである。要求工学（requirements engineering）は、その追放された目的を、実務の必要から形式的な市民権とともに再入城させた学問である。アリストテレスの四原因説は、その再入城の地図として提示する。単なるオマージュではない——四原因説は、現代の要求分析ツールが「なぜ未だ分割できていないか」を示す、2300年早い診断表である。

### 四原因 — 説明の四方向

アリストテレスは『自然学』第二巻で、変化の説明には四種類の「なぜ」があると説く。用語を現代語に翻訳して置こう。

**質料因（material cause, hyle）**：何から作られているか。 bronze（銅）が銅像の質料である。ソフトウェアで言えば、実行資源・データ・既存資産（レガシーコードも質料である——質料は形状を抵抗し、抵抗が設計を規定する）。

**形相因（formal cause, eidos）**：何であるかを決める形・構造。図像の輪郭。ソフトウェアではアーキテクチャ、データモデル、オントロジー——**定義そのものが原因として働く**という発想は、形相因の復活である（→1.5の「ラベルは存在論的宣言」、→2.4のTBoxがABoxを制約する構造）。

**動力因（efficient cause, kinoun）**：何によって作られたか。彫刻家。現代では「作業者・プロセス・CI/CD・エージェント」（→3.6のエージェントモデルは動力因の形式化である）。

**目的因（final cause, telos）**：何のために作られたか。銅像の場合は「飾られた広場を美しくすること」。近代力学はこれを自然から追い出した（目的なしに物体は動く）。だが人工物から目的を追い出すことはできない——人工物に目的がなければ、それは完成の定義を持たず、完成の定義を持たない人工物の良否は測定不能になる。

この最後の推論を、要求工学の中心定理として置いておく。**目的因を持たないシステムの良否判定は原理的に不可能である。** 性能指標（speed、uptime）は形相因と動力因の内部測度にすぎず、「できばえ」の判定には「何のために」が必要である。KPI が暴走するとは、目的因なしに形相因の指標が目的のふりをする現象の名前である。

### 四原因と現代の要求モデル — 診断表として使う

要求工学の標準的な概念を四原因で再配列すると、未分割の問題が見える。

| 四原因 | 要求工学での継子 | よくある未分割事故 |
|---|---|---|
| telos | ゴール・ビジョン・softgoal（→3.2） | 「要求文書にあるが telos がない」——機能は列挙されているが目的文が無い |
| formal | データモデル・オントロジー・受入条件 | 目的文なしに形相が先行し、「作れるが要らないもの」が完成する |
| efficient | チーム・プロセス・実装主体 | 「誰が実現する（whether it can be done by this team）」が目的分析の後で初めて問われる |
| material | 既存資産・制約・技術的負債 | レガシーを「障礙」扱いし「質料」扱いない——質料は設計を規定する（→3.4の障礙分析の区別） |

最終行の区別を強調する。障礙（obstacle, →3.4）と質料（material）は違う。障礙は「ゴールを妨げる出来事」であり除去対象だが、質料は「ゴールを実現する媒体」であり、質料を無視した設計は障礙を無限に発生させる。レガシー資産を障礙台帳に載せる組織は、永遠に障礙を除去し続ける。質料台帳（技術的負債の「資産」としての棚卸し）を書く組織だけが、形相を質料に適合させる——アリストテレスで言えば、質料に先立つ形相は存在しない。

### telos の形式化 — 「目的」を論理式に翻訳する手順

それでは telos を形式化できるのか。できる、ただし限定付きで。telos の「内容」（なぜその目的を選ぶのか）は形式化できない——これは実践知（phronesis）の領分であり、第5部まで引っ提げる残題である。形式化できるのは telos の**構造**である。「G は S のために存在する」という関係の構造——実現関係・充足関係・優先関係——を論理で記述できる。要求工学のゴール指向分析（→3.2, van Lamsweerde）は、まさにこの構造の学である。

telos 記述の最小構文を、本書のオントロジーに載せる形で定義する。

```cypher
// ゴールの telos 層: 「G は P のためにある」を辺で持つ。
// 目的の正当化は別の Goal ノードとして、無限後退を許容する形でつながれる。
// 無限後退を「許容する」のが要点である。telos 連鎖の末端（axiological root）は
// 人間が引き受ける価値であり、論理の外に置く。論理の外に置くことを形式化する。
MATCH (g:Goal {goal_id: $gid}), (p:Goal {goal_id: $pid})
CREATE (g)-[e:ACHIEVED_FOR {
  justification: $free_text,      // 自由文必須。「なぜなら」を機械に書かせない
  depth: 2,                       // telos 連鎖の深さ。3以上でループ警戒flag
  axiological_root: false         // 末端はこの flag で宣言される
}]->(p);

// 循環検出: telos 連鎖は循環してはならない(目的が目的を循環して支えるとき、
// システムは内部で自己正当化する)。
MATCH path = (g:Goal)-[:ACHIEVED_FOR*3..]->(g)
RETURN g.goal_id, length(path) AS cycle_len;

// 孤立ゴール検出: ACHIEVED_FOR の上向きの辺を持たないゴールは、
// 「そのために存在する目的が無い機能」= telos 不在の機能。
// 本章の診断定理により、これらの良否判定は原理的に不可能である。
// 放置ではなく「telos を持つことを放棄した機能」として明示的にラベルする。
MATCH (g:Goal) WHERE NOT (g)-[:ACHIEVED_FOR]->()
SET g.orphan_goal = true,
    g.abandonment_declared_at = datetime();
```

`abandonment_declared` の設計判断を説明しておく。telos の無い機能は存在してはならない、と厳格にやると、現場は telos を嘘で埋める（「安全のため」「効率のため」）。目的文のインフレは telos のない世界より悪質で、目的が偽名で保護された無目的は批判の対象から外れるからである。したがって、孤立を罪ではなく申告された状態として扱う。孤立申告率は組織の健全性指標になる——嘘で塗り固めた組織は孤立申告ゼロになる（この指標のゲーミング対策は 4.6 の契約テストと結合する）。

### 目的因の追放と復権の歴史 — なぜ近代はこの問いを失ったのか

telos 復権を「アリストテレスを戻そう」というノスタルジーとして読まれたら困る。追放には理由があり、理由は現在も有効である。近代的自然科学は、目的を自然に認めた瞬間に万物有霊化へ退行する（石が落下するのは「落りたい」という目的のためか、という難問）。目的を自然から追放した代わりに、近代は目的を**主体の設計**へ退避させた。人工物にのみ目的を認める。しかしこの退避は不安定である。主体（設計者・人間）を自然の一部と認めるなら、人工物の目的も自然現象の一部であり、追放は自己言及的に崩れる。生態学と行動経済学は今日、自然の中に「機能」「適応」「ヒューリスティクス」という目的に似た語彙を戻している。

本書の設計の立場からすると、この二百年の揺れの実務的教訓は次の一文になる。**目的を形式化から追放すると、目的は形式化の外から（隠れた形で）システムを支配し続ける。** 「最適化」の目的を宣言しないデータパイプラインは、最後に残った計測可能な指標（ログ行数、レイテンシ）を目的として黙って採用する。目的の不在は中立ではない。既定値が目的になる、という静かな発火事故である。

第1章の暗黙知、第2章の分類の暴力と、ここでの telos は同じ主題の三面である。**明示されなかったものは、不在ではなく、既定値として効く。** 暗黙知は形式化の外で知を規定し、残余は分類の外で意味を規定し、未宣言の telos は目的の外で評価を規定する。第2部の仕事は、三つの「外」をそれぞれ形式化の縁に引き寄せることだ——障礙分析は残余の形式化（3.4）、competency questions は残余の意味の形式化（4.2）、goal tree は telos 連鎖の形式化（3.2・3.3）にほかならない。

### 現場の失敗例 — telos なき自動発注システム

抽象論を、実際に起きた型の失敗で締める。ある部品の在庫システムが「欠品の自動検知と自動発注」を導入した。要求文書には機能（形相因）とベンダーと開発体制（動力因）、ERP連携と在庫データ（質料因）が書かれていた。telos の欄には「在庫最適化」と書かれていた——これは telos ではなく形相的な指標である。真の telos——「ライン停止をゼロにし、その上で在庫資金を最小化する」——は書かれていなかった。結果は教科書通りである。システムは欠品を検知し、発注し、欠品は減った。在庫資金は倍増した。どちらの指標も「最適化」されたから、システムは要求通り動作した。**要求は満たされ、目的は裏切られた。** この一文を要求工学の第一定律として記憶してほしい。telos の形式化（goal tree と softgoal の競合記述、→3.2・3.6）は、この定律を破綻前に検出するための唯一の機械的装置である。

### 目的因の復権を組織設計に橋を架ける — 四原因のチェックリスト運用

四原因説（→前掲の material/formal/efficient/final）を、要求レビューの運用チェックリストとして実装する。哲学者の分類を会議の語彙に変えるのは、**目的因の欠落が個人の不注意ではなく、会議の進行手順の欠陥**であることを証明するためである（構造の設計で人格を治療する——本書の一貫した方法）。

レビューの各項目に、検査質問と不合格時の登記先を定める。**材料因**「この要件は、どの実在（観測・データ・既設機構）の上に立つか」→ 実在の参照が一つも無ければ goal の root 欠落として障礙候補登記（→3.4）。**形式因**「この要件の完了状態は、どの構造の完成として記述されるか」→ 構造語彙（グラフの語、→1.3）で書けない要求は CQ 化して審議槽へ（→4.2 の問いに直す設計）。**作用因**「誰が・どの資源で実現し、中間成果物の連鎖は何か」→ 作用因の記述は委任設計の入力になる（→7.2 の mission packet の assumptions）。**目的因**「これは何のためにで、その上の目的が今も有効か（落日・実測）」→ 目的因の鎖条が E4 前提（→4.1）で期限切れなら、レビューは要求の妥当性を論じる前に前提の再承認を要求する。

```python
# review_gate.py — 四原因レビューの機械検査(会議前の自己申告をデータ化)
class RequirementReview(BaseModel):
    req_id: str
    material_refs:  list[str]     # 材料因: 実在参照(≥1)
    form_struct:    str | None    # 形式因: 完成状態の構造記述(graph:// URI)
    agents_budget:  dict | None   # 作用因: 主体と資源
    telos_chain:    list[str]     # 目的因: goal_id の連鎖(root まで)
    def holes(self) -> list[str]:
        h = []
        if not self.material_refs: h.append("material")
        if not self.form_struct:   h.append("form")
        if not self.agents_budget: h.append("efficient")
        if not self.telos_chain:   h.append("final")
        return h
```

`holes()` の返す穴の名前が、そのまま会議の議題になる（原因の名前は欠陥の名前でもある——四原因は完成形の分類ではなく、**欠陥の四分法**として実運用される）。目的因の穴が最頻である事実を、レビュー統計（holes の分布）として四半期に一回報告する——この統計が組織の「目的の空洞化」の唯一の定量証拠になる（→4.6 の scorecard の要求工学版）。

最後にアリストテレスへの最深的な注釈を置いておく。四原因説の近代における追放（力学が材料因と作用因だけになり、目的因が「主観的価値」として科学の外へ追いやられた——→2章・5章の事実/価値切断の系譜）は、要求工学の「目的を書く場所の欠如」として戻ってきた。目的因の復権とは、古代哲学の輸入ではなく、**追放されたはずのものが現場で必要され続けていた**ことの発見である（→telos は消えたのではなく、書けない語になっていた——書ける語に戻す作業、→1.4 の可言明化の設計が、ここで三千年前の分類にまで及んでいる）。

### 目的の時制 — 近い目的と遠い目的の衝突を goal 木で検出する

目的因（→前掲）は単独で老朽化するのではなく、**目的同士が時間で衝突する**。短期 KPI（今期の稼働率）と遠い目的（設備寿命・技能継承）が goal 木で兄弟・叔父甥になる時、機械的に検出できる衝突が生まれる。設計は二つ。**其一、goal 節点に時間地平（horizon: near/far）を載せる**（near = 当期 act で到達、far = 落日周期 12 か月超）。**其二、near goal の effect が far goal を NEGATES（→3.4 N2）する辺を、goal 木レビューの自動照会に出す**——「稼働率を上げる act 列が、継承（→終章）の far goal を壊している」型の構造は、会議では「どちらが重要か」の意見分裂に化けるが、goal 木では**辺の欠落**として表示される（NEGATES の辺が結ばれていない=冲突が未知、3.2 検査三の完全性宣言の目的間版）。

```cypher
// telos-time-conflict — 近い目的→遠い目的の妨害辺(未知の冲突)を発見
MATCH (n:Goal {horizon:'near'})-[:HAS_SUBGOAL*0..2]->(:Goal)-[:HAS_ACTION]->(a:Action)
      -[:EFFECT]->(e)-[:NEGATES]->(f:Goal {horizon:'far'})
RETURN n.goal_id AS near_goal, a.act_id, f.goal_id AS far_goal
UNION
// 未宣言の冲突: effect が far goal を削る統計的痕跡(実測側)
MATCH (a:Action)-[:EFFECT_MEASURED {sign:-1}]->(f:Goal {horizon:'far'})
WHERE a.at > datetime() - duration('P1Q')
RETURN a.act_id, f.goal_id, 'undeclared-telos-erosion' AS kind;
```

`undeclared-telos-erosion` の意味をこの節の主題に接続する——遠い目的は act による侵食を**実測でしか知らない**（宣言された NEGATES 辺は設計者の想定、実測の sign=-1 は世界の返答。両者の差分が 3.3 の翻訳表と放棄表の目的版——宣言されず侵食されている目的は、放棄表にも載っていない目的である）。遠い目的の落日（→3.1 telos_chain の落日設計）は、この侵蝕統計の閾値発火で促される：far goal への侵蝕が 2 四半期続いた時、落日審議は「far goal を消すか、near goal の act を制限するか」の二択を強いられる——**目的の消滅はつねに、どちらかの会議で署名される。署名されないまま消えるとき、目的は事故で消えた**（→2.5 の簿記の伦理、→6.6 腐敗の目的版）。

### 目的台帳の運営 — 会議冒頭の四行の質問

telos_chain（→前掲）を台帳として活着させる最小運営を置く。会議の冒頭、アジェンダの全議題に四行を先行させる。**其一**：この議題が触る goal の URI（触る goal が書けない議題は、目的なき作業の候选—→3.1 の final cause 欠落の現場検出）。**其二**：その goal の落日周期と前回審議時刻。**其三**：その goal の亲（遠い目的）の名前を一人が自分の語で言う（形式化された goal の文でなく**個人の語**で言わせる—→8.1 の site_coinations と連動、言えない亲は目的の連鎖が個人レベルで切れている—→3.1 の鎖の個人内側）。**其四**：議題の act 候補が effect 側でどの goal を削るか、既知のものだけ挙げる（未知は N2 の障礙候选—→3.4）。

```cypher
// meeting-open — 議題の目的接続を自動引く(会議ボードの照会)
MATCH (i:AgendaItem)-[:TOUCHES]->(g:Goal)
OPTIONAL MATCH (g)-[:TELOS_UP*1..3]->(far:Goal)
RETURN i.id, g.goal_id, g.sunset, far.goal_id AS telos_chain,
       g.last_deliberated;
```

この四行が会議のたびに回ると、目的台帳は「書いてある書物」でなく**読み上げられる儀式**になる——形式知が生き続ける条件が使用の反復であることは 1 章の暗黙知の論証そのもので、目的台帳もまた使われなければ 2.3 の制度老化一直線である。四行の質問の四半期ログ（議題総数対「触る goal 書けず」の比率）が、組織の目的相関の健康度である。

### 実行練習

1. あなたの中核システム1本について、四原因診断表（上の表）を自分の語彙で書き、各欄に「書いてある/嘘で埋めてある/空欄」を印せ。空欄と虚偽の総数が telos 負債のサイズである。
2. 上の孤立ゴール検出クエリを自分の要件定義書から作った `Goal` ノード20個で走らせ、孤立申告率を算出せよ。申告率が15%を超える場合と5%未満の場合で、組織の何が違うかを telos インフレの概念を使って説明せよ。
3. 「在庫自動発注」の telos を goal tree の形で10ノードに分解し、softgoal「資金最小」と「停止ゼロ」の競合を1つ ACHIEVED_FOR でなく `CONFLICTS_WITH` 辺として記録せよ。競合の調停は論理では決まらない（両 softgoal の正しさは両立可能）——調停者として誰を置くべきか、級 L2 の変更手続（→2.6）を援用して決めよ。
