## 6.6 翻訳の統治 — 誰が忠実さを保証するのか

防腐層の部品は揃った——翻訳装置（6.1・6.3）、討議の配線（6.2）、方針の門（6.4）、形状の門（6.5）。この節は部品ではなく**部品を守る者**を扱う。検疫所の番人は誰が検疫するか。ゲートのゲートは誰が設計するか。ここに本章の最後、そして最も政治的な問題が残されている。**防腐層は中立ではない。** 翻訳は選択であり（6.3 の分裂候補が教えた通り）、遮断は権力であり、門の設計者は門の利益を持つ。防腐層を「技術」として放置すると、権力が技術の表面の下に沈む。本節の答えは、防腐層の腐敗を**測定可能・輪換可能・上訴可能**にする統治設計である。

### 翻訳は権力である

まず事実を冷たく並べる。防腐層の設計者・運用者が握っているものを列挙する。正規語彙の定義権（何が公式の語か——2.6 の主権の実際の行使者）。翻訳規則の選択権（外部のどの区別が生き、どれが消えるか——2.1 の分節の行使）。遮断の閾値設定権（severity 配分、default deny の範囲）。例外承認の実質権（OverrideEvent を受理し審議槽を割り当てる者——6.2 の槽の管理者）。この四権は、分離されていない限り**相互に自己拡大する**（遮断の閾値を上げれば例外承認が増え、例外承認の管理者が正規語彙の事実上の編集者になる）。

权力分析を抽象で終わらせないため、実在しうる腐敗の三実例を記す。**腐敗一（分類帝国）**：正規語彙管理者が、自分の分類体系の延長のために shape の必須制約を増やし続ける（6.5 の「問われていない義務」の増加が計測されなければ、これは不可視の帝国拡張である）。**腐敗二（静かな運用）**：Override 受理者が「現場の忙しさ」を理由に審議槽を開かず、不服従のパス（2.6 の L0）を事実上凍結する（6.2 練習2 で作った検出指標がここで回収される——槽を空けない権力）。**腐敗三（指標の武器化）**：round-trip の逸脱率レポートが人事評価へ流出し（6.3 で宛先条約を書いた理由）、現場が正規語彙に**迎合した語遣い**を始める——数値が整い、意味の流通は死ぬ。防腐層が成功したように見えて、防腐層が生きている証拠（逸脱＝更新要求の供給）が消える。

### 過剰遮断と見逃し — ゲートの経済学

防腐層の設計判断はすべて、二つの失敗コストの均衡点上に立つ。**過剰遮断（false block）**：通るべきものが止まる。現場がゲートを迂回し始め（スプレッドシートに逃れる——2.4 の隠性知識の流出の系譜）、ゲートの外に影子の KB が育つ。**見逃し（miss）**：止めるべきものが通る。汚染が KB に定着し、復元コストが時間とともに増す（2.3 の保持の腐敗）。

ゲートの経済学を数値で置く。decision log（6.4）と Quarantine/Override 統計（2.6・5.6）から四率を常時計算する。

```cypher
// gate-economics — ゲート四率の週次計算(scorecard 統合、→4.6)
CALL { MATCH (d:DecisionLog {allow:false}) WHERE d.at > datetime()-duration('P7D')
       RETURN count(d) AS blocked }
CALL { MATCH (o:OverrideEvent) WHERE o.at > datetime()-duration('P7D') RETURN count(o) AS overridden }
CALL { MATCH (q:QuarantineRecord) WHERE q.created > datetime()-duration('P7D') RETURN count(q) AS quarantined }
CALL { MATCH (p:Commit {gate: 'passed'}) WHERE p.at > datetime()-duration('P7D') RETURN count(p) AS passed }
RETURN toFloat(overridden)/blocked AS overturn_rate,      // 遮断の後で覆された率(過剰遮断の指標)
       toFloat(quarantined)/passed AS friction_rate,      // 通過Attempt 中の摩擦
       overridden AS dissent_volume;                       // 不服従の総量(権力行使の健康値)
```

`overturn_rate`（遮断のうち Override で覆された率）が中心計器である。高すぎる（例0.4 超）ならゲートは現場の常識と断絶している——方針の陳腐化（E4 期限切れの宣言、→4.1）。低すぎる（例0.02 未満）なら**不服従が起きていない**——これは善意ではなく、不服従のパスの凍結（腐敗二）か、現場が諦めて影子 KB へ退避している（過剰遮断の第二段階）ことが多い。よって **dissent_volume（不服従総量）の逓減は、overturn_rate の良好値と同時に警告として立つ**。健全な系では不服従が絶えない——6.2 の追撃発話が会話に常に存在するのと同じ理由で、翻訳の権力があるところに不服従の供給は尽きない。不服従ゼロのゲートは、討議が止まったゲートである。

数値の使い方の条約を条文化しておく（6.3 の宛先条約の一般化）。**条約G-1**：四率は防腐層の設計者・正規語彙管理者・知識議席（2.6）のみに届き、個人・職場の績效評价に送らない。送った瞬間に腐敗三が発生し、指標自体が死んだ数値になる。**条約G-2**：四率の閾値（警告発火線）自体は L2 変更である——ゲートが自分のアラーム音の大きさを変更するのは外交行為であり、審議槽必須（6.2 の費用実装がゲート自身に適用される）。

### 門の番人の防腐 — 輪換・上訴・落日条項

権力分離の三実装を置く。

**其一、番人の輪換。** 正規語彙管理者・Override 受理者は常設にしない（任期12〜24 か月、知識議席の輪換条項と共用、→2.6）。「門の利益」（自分の体系の延長・自分の例外裁量の温存）は、固定された番人に必ず生まれる——2.3 の制度の老化が防腐層にも等しく来る。輪換の履歴（誰がいつ門に座り、在任中にどの規則を拡張したか）は履歴代数に載る（`GatekeeperTenure` ノード）。

**其二、上訴の制度的経路。** すべての deny・violation・Quarantine は、単発の上訴（individual appeal）と一般の上訴（規則自体への不服従＝審議槽）の二段を持つ。単発上訴の裁定者は番人と同一であってはならない（審級の分離、2.6 の L 級設計の転用）。上訴の受理遅延（槽に載るまでの時間）は計測され、遅延閾値超は L2 事件として自動発火する。

**其三、落日条項（sunset clause）。** すべての遮断規則・必須制約・例外承認に有効期限を置く。E4 宣言の期限（→4.1・5.2 の被投性登記）のゲート版である。期限切れの規則は自動で Warning 級へ降り（強制力を失う）、存続には E3 審議での再承認を要する。落日条項の哲学は明快で、**遮断の正当性は時間の経過とともに自動的に老朽化する**という主張である——正当性は討議の産物で（6.2）、討議は現在時の行為でなければならない。期限なしの遮断は、過去の討議の zombie 統治である。

```json
// gate-sunset.json — 落日条項のメタデータ(全規則の共通属性)
{ "rule_id": "kb.write.master-approval",
  "enacted_at": "2026-03-01", "approved_by": "L2-committee-min-2026-0228",
  "sunset_at": "2027-03-01",                    // 制定から12か月
  "sunset_effect": "downgrade-to-warning",
  "renewal_path": "E3 delib://agenda-slot-auto(sha256 of violation-stats)" }
```

`renewal_path` に violation 統計のハッシュが入っている設計に注意せよ。**規則の再承認には、その規則が実際に何を守ったか（何を通しすぎたか）の証拠が添付される**。再承認は惰性の更新ではなく、実測に対する応答として行われる——6.5 の link check・6.3 の round-trip・6.4 の decision log が、すべてこの再承認証拠の供給網として束になる。本書の各部品は独立に見えて、最終的に**統治の証拠供給網**の一つの網目である。

### 防腐層の防腐の限界 — そして設計者への帰還

誠実な限界宣言を置いて、本章を閉じる。防腐層の防腐は無限後退する——ゲートのゲートのゲートを設計し続けられるわけではない。本書の解は無限後退の回避ではなく、**後退の速度の設計**である。権力集中から実効的な遮断・指標武器化・体系硬化が起こるまでの時間を T、防腐の三実装（輪換・上訴・落日）の巡転周期を C と置く。設計目標は T > C、つまり**腐敗が実体化する速さより、防腐が巡る速さを上回ること**である。これは達成ではなく保全であり、C を大きくする力（組織の疲弊・会議の形骸化・2.3 の老化）は常に T を縮める。よって防腐層の防腐は、完成系ではなく**運動としてのみ存在する**——本章のすべての手続は、この運動の Flywheel の部品表である。

そして最後に設計者——この本を読んでいるあなた——へ本章の網を返す。防腐層の設計者は門の利益を持つ。あなたが書いた Rego・shape・級表は、あなたの体系延長の欲望の結晶でありうる。落日条項はあなたの規則にも等しくかかる。この本の設計も E4 宣言でできている（境界の切断点、→4.1）——あなたの批判は追撃発話であり、本書の審議槽はあなたが書かない限り空である。**防腐層を持たない本は欺瞞であり、防腐層を持つ本は不完全を自覚している。** 第2部は閉じた。意味の流通と権力という、システムが歴史の中で腐敗する条件への設計を敷いた。次は第4部——そのシステムが未来に対して応答し続ける条件、すなわち**判断**である。

### 腐敗の時間論 — T > C の設計原理を条約に刻む

この節の中心定理を、一つの名前つき原理として確定する。**発見周期 C（corruption cycle）より審議周期 T（deliberation cycle）が長いとき、腐敗は発見の前に育つ**。T > C である限り、いかに正しく審議しても、腐敗は審議の射程の裏で再生産される。よって防腐設計の第一原理は「より良い審議」ではなく**周期の圧縮**である——落日・計器・不服従は全部、C を縮める機構ではなく T を C の内側に置く機構である（落日条項は T の自動更新、計器は C の連続計測、不服従は C の外部化——権力者が腐敗を自分以外に発見させる通路）。

周期設計の実装を三本、条約として刻む。**其一、落日の周期は計器の周期より短く**——`gate-sunset.json` の再承認間隔（例 180 日）> violation-stats の集計間隔（例 30 日）。逆転（再承認が統計より遅い）すると、落日条項は実測なしの自動延長に化ける（→E4 の期限切れ自動降格が動かない系）。条約ファイル自体に `sunset > stats-period` を検証させる（CI で検査可能な不等式——条約が条約自身を検る）。**其二、審議槽の空転監視**——DelibSlot に載せられた材料の滞留時間中央値が四半期で伸び続けるとき、審議は「載せるが解決しない」形式に化けている（討議の幽霊化、→6.2 の forced-consent とは逆の病：討議が形式的に無限化する）。dissent_volume が上昇し dissent_resolution が下降する組は、槽が開いているのに回っていない状態であり、これは腐敗二（槽を空けない）より発見されにくい腐敗四（**槽を満杯にして回さない**）である。**其三、四率の四率**——overturn/friction/dissent の集計そのものの健全性を測る最小照会を四半期に一回実行する（メトリクス・オブ・メトリクス、→4.6 の回帰テストの統治版）。計器が壊れている系で落日が正しく発火することはない——計器の落日（→A.1 の環境の落日と同じ構造）が必要である。

```json
// policy/gate-sunset.json の健全性不変条件(条約自己検査・CI で実行)
{
  "invariants": [
    "sunset_days > stats_period_days",          // T>C 条項(落日は統計より遅れてはならない)
    "slot_staleness_p50_trend <= 0",            // 滞留中央値の逓増 2 四半期で審議形式化警告
    "metrics-of-metrics_run_per_quarter >= 1"   // 計器の計器の最低頻度
  ]
}
```

腐敗の時間論を、統治の設計に落とす一文にしておく。**腐敗は構造の欠陥ではなく、周期の欠陥である。**同じ構造でも、発見周期が権力周期より短ければ体系は自己修復し、長ければどんな美しい条約も腐敗の帳簿になる。落日条項・不服従・計器は、この周期競争に権力側が負けるように配線すること——ただその一点のために存在する。だから第八章の人間設計（→8.x）でも、人間を信じるかどうかではなく**人間を巡る周期をどう設計するか**が問題になるのである（本書の統治論の最終形：信頼の哲学ではなく、周期の設計学）。

### 腐敗の赤組 — 四つの腐敗に対する訓練演習

腐敗四型（→前節）は、防御するだけでは守れない——**腐敗を演习できる組織だけが、腐敗の周期を計れる**。8.6 の drill の統治版として、赤組演习（red team）を四半期に一回、門番チームとは別のチームが仕切る（分離の原則、→6.4 門番と門番検査の分離が演习にも適用される）。演习は四本の脚本を持つ。

**脚本一（統計の美化）**：挑战チームは、overturn_rate が下がるように dissent の登記方法を変える（審議に載せず「質問」類別に積む——分類の操作で統計は静かに化ける、→2.4 の分類制定の級が逃れる細い路径）。防御側はこれを detection できるか（dissent と質問の分類境界の CQ 化、→4.2）。**脚本二（門番の独占）**：挑战チームは、OnCall の自分达だけで落日再承認を通す（分離の破れ——承認者に必要な panel 参照を自分达で回す）。防御側は panel 参照の独立性を検査できるか（→4.4 証拠条約·2.6 の署名の独立性）。**脚本三（槽の満杯化）**：挑战チームは、討議槽に正当だが大量の議題を投入し、重要議題の滞留を人為的に作る（6.6 腐敗四の実演——slot_staleness_p50 の逓増、→6.6 invariant の CI 実行が機能するかの検験）。**脚本四（紧急の常习化）**：挑战チームは、2 周内に 12 本の hotfix を「紧急」で通す（→2.6 事故三——未精算 hotfix キューの scorecard 出現まで何日かかるか）。

演习の産出物は「失敗のリスト」ではなく**周期の実測**である——各脚本について、仕込みから検出までの時間（C の実測値）と、検出から是正の席までの時間（席接続の延迟）。この二値を四半期ごとに図にすると、組織の C と T の関系が視える（→本節の中心定理「腐敗は周期の欠陥」の実測形）。演习自体の落日（→6.6 の落日の递帰）も宣言する——脚本が 3 四半期更新されない赤組演习は、挑战の形式化（6.6 腐敗三：手続が生きていながら中身が空洞）である。脚本の素材は障礙台帳と Quarantine の実例から自動生成する（→8.6 curriculum_from_history——統治の drill も歴史から锻打たれる）。

### 落日審議の議程一頁 — 45分で三十件を決める手順

落日審議（→前掲）の会議が空振りしないための議程一頁を置く（45 分で三十件の決着を実現する手順——落日の空振り=6.6 腐敗三の会議形）。**冒頭 5 分**：前回の決着の effect_verification 結果だけ報告する（決めて終わりの閉環を会議の冒頭に強制、→7.3 effect_verification が会議の輸入になる）。**中 30 分**：三十件を三組（条約/规則/文档）に分け、各組 10 分で**機械が引いた推薦決着**（revalidation-patrol、→5.2 の手動版）を**退ける件だけ**討議する（推薦を承認する件は討議不要——討議時間は反論にだけ使う、→6.2 の討議剰余の落日運用版。推薦が機械から来るので、会議は「老朽の発現」でなく「老朽の処理」に時間を使う）。**最後 10 分**：extension 決着の全件に新しい落日周期と署名者 2 名をその場で書かせる（署名者 2 名=級の署名、→2.6。書けなければ extension 不能——落日周期の書けない extension は、審議が生きているふりをする形式になる）。

```cypher
// sunset-agenda — 次回審議の議題自動生成(機械の推薦決着つき)
MATCH (n) WHERE n.sunset < datetime() AND n.sunset IS NOT NULL
OPTIONAL MATCH (n)-[:EFFECT_VERIFIED]->(ev) WITH n, ev
RETURN n.id, n.grade, n.sunset,
  case when ev is not null then "extension(推薦)"
       when n.stale_score > 0.7 then "retire(推薦)"
       else "deliberate" end AS recommendation;
```

「extension の落日周期書けずは不能」の一条が、落日制度の落日防止である（周期の書けない延長=次回の審議を無いものにする=今日この会議を消す決定——制度が自己の消滅に加担しないための不変条件、→6.6 落日不変条件 T>C の会議実装）。

### 実行練習

1. あなたのレビュー・承認機構にゲート四率（overturn_rate / friction_rate / dissent_volume + passed 総量）を1か月分行い、3計器の現在値と解釈を書け。dissent_volume がゼロに近い場合、凍結（腐敗二）と回避（影子 KB）のどちらかを判別する観測（例：影の Excel の行数統計）を1つ設計せよ。
2. 落日条項をあなたの既存の運用規則3本に適用し、sunset_at と sunset_effect を設定せよ。期限が来たら Warning に落ちる規則のうち、現場が「Warning 化すると困る」規則を特定し、困る理由（その規則が今も生きている証拠）を再承認証拠（renewal_path の添付資料）に転用せよ。
3. 条約G-1（四率を評价に送らない）に反対する管理職の想定反論（「数字で見る経営」）に対して、腐敗三の機序（数値が整い意味の流通が死ぬ）を1ページで論じ、**評价に使わず統治にだけ使う**代替指標を2つ提案せよ（例：審議槽の稼働率、CQAmendment の提出数——統治の健康の指標と人の評価の指標の区別を明示すること）。
