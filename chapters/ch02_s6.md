## 2.6 版管理の倫理 — 誰が分類を書き換える権利を持つか

2.5の墓標クエリが教えてくれる最も不快な事実は、技術的なものではない。「意図なき変更」の列が長い組織では、分類の変更が誰かの仕事の一部として、誰の判断でもないままに行われている。差分は追跡できても、責任は追跡できない。git の author はコードを書いた人であり、意味を決めた人ではない（→2.5 の `:gap`）。この節では、分類の書き換えを**権利の問題**として設計する。版管理の倫理という語は飾りではない。変更履歴の不変性、承認の署名、不服従の記録——これらはすべて機械に強制可能なポリシーの実装物であり、ポリシーの実装は権力の配置そのものである。オントロジーの版管理システムは、その組織が「知識の変更を誰に認めるか」を書き記した憲法である。この節の終わりには、その憲法を Rego で書き、沈黙の猶予期間を機械に守らせるコードが手元にある。

### 分類権限は組織権力のコッド化である

まず事実関係を冷徹に並べる。オントロジーを変更できる状態にあるのは、次の四つの権限のどれかを持つ者だけである。(1) リポジトリの push 権限。(2) マスター語彙の名前空間の所有権（DNS 管理下にある場合）。（3） reasoner ゲートを通過させる CI の設定権。(4) ゲート例外（override）の発動権。

この四つは組織図から独立に割り当てられうる。典型的な事故は、権限の配列と知識の配列がねじれたときに起きる。現場の作業者は第3章で言う competency question の答えを知っているが (4) を持たず、プラットフォームチームは (3)(4) を持つが現場を知らない。このねじれを「技術的な権限設定の問題」と呼ぶか「統治の問題」と呼ぶかで、設計の運命が変わる。前者は ticket の問題として消え、後者は設計対象として残り続ける。

エヴァンスの DDD が限界コンテキストの所有権を組織に自覚させる道具だったことを思い出そう（→6.1）。本章の文法で言い換えれば、**語彙の名前空間は主権であり、マッピングは外交である**。主権の変更手続（語彙の削除・退位・意味変更）と、外交手続（`exactMatch` の格上げ）は、異なる承認フローを持たねばならない。同じフローで扱った瞬間、外交の蓄積が主権の侵食に転化する——現場語彙がマスター語彙に静かに同一化されていく 2.4 の `sameAs` 事故は、手続の欠落が産む地政学的変化である。

### 承認フローの設計 — 変更の種類に応四段階

承認を一律にすると二つの失敗のどちらかになる。軽微な変更が承認待ちで詰まり、現場語彙の追加が事実上止まる（知識の新陳代謝の停止）。あるいは全員承認の形骸化（承認が署名の儀式化）。回避するには、変更の不可逆性に応じて段階化する。

| 級 | 変更の型 | 例 | 承認 | 猶予期間 |
|---|---|---|---|---|
| L0 | 追加のみ（既存語彙に非干渉） | 新類義語の `closeMatch` 追加 | 提出者＋レビュー1名 | なし |
| L1 | 対応の変更 | `closeMatch` の方向変更 | 語彙主権者＋被影響語彙主権者 | 7日 |
| L2 | 意味の変更 | クラス定義の修正、`exactMatch` への格上げ | 承認委員会 | 30日 |
| L3 | 不可逆変更 | 退位・統合・列挙値の削減 | 委員会＋影響受ける現場の代表 | 90日＋沈黙の猶予 |

注意すべきは、級が「変更の大きさ」ではなく**不可逆性**で決まる点である。追加（L0）は取り消しが自由である。統合（L3）は、統合された二つの語の境界を復元するコストが時間とともに無限大へ発散する（境界を知っていた人が辞めるため、1.6・8.1）。不可逆性の測定は 2.5 の履歴代数で可能である——`retracts` された主張の `rawText` を復元照会できる残り人数、という代理指標を CI で計算させればよい。

```rego
# change_class.rego — 級分けの自動化（L0〜L3 の機械判定）
# 哲学: 級の判定を人にさせると、人は「小さいから L1 で」と交渉する。
# 不可逆性は交渉可能にしてはならない。機械が級を決め、人だけが猶予を短縮できない。
package execphil.classify

default level = "L3"

level = "L0" {
  only_additions
  no_master_vocab_touched
}
level = "L1" {
  only_mapping_changes
  not exactmatch_promotions
}
level = "L2" {
  semantic_definition_changes
  not irreversible
}
# irreversible の定義: retracts に deprecated/union/cardinality-reduction が含まれる
irreversible {
  some i in input.commit.retracts
  contains(input.commit.retracts[i].rawText, "owl:deprecated")
}
irreversible {
  some i in input.commit.retracts
  contains(input.commit.retracts[i].rawText, "AllDisjointClasses")
}
irreversible {
  contains(input.commit.intent, "union")   # 統合の自己申告を騙さない。語彙解析と二重checks
}
only_additions { count(input.commit.retracts) == 0 }
```

### 不服従のパス — 承認フローは忠誠の機械であってはならない

承認フローには構造的な暴力が内蔵されている。フローは「承認された変更しか存在しない世界」を作る。2.1 の暴力論の語彙で言えば、フローは残余の記録を拒否する——承認されなかった提案は、履歴にすら残らないことが多い。これは最も深い型の脱知識化である。提案が「検討の結果、不採用」ではなく「提出されなかった」ことになると、2.5 の墓標すら建たない。

したがって、フローは**不服従のパス**を持たねばならない。三つの装置を設計に組み込む。

**第一に、却下された提案の墓標化。** 承認委員会が棄却した提案は、L3 と同じ粒度で `RejectedProposal` として保存され、`intent` と棄却理由（自由文・必須）を持つ。再提案は同じ墓標への参照として行われ、棄却理由の更新なしには通らない。棄却理由の更新は、棄却の歴史を消さずに否定の否定を行う操作——Aufheben の手続形である（→2.2）。

**第二に、現場の unilateral 記録権（一方向の権利）。** 現場はマスター語彙を変更できないが、**自語彙からのマッピング提案を履歴として提出する権利**を止められない。L0 で提出され、承認されなくても、2.5 の履歴代数に載る。承認されなかったマッピングは HEAD には効かないが、墓標クエリには現れる。効かない主張が履歴に残るという設計は、ハーバーマス的な妥当性要求の空間の確保である——真実性・正統性の主張は、承認されなくても発話されうる（→6.2）。

**第三に、override の目録化。** ゲート例外（CI 無視・force merge）は技術的に防止しない。代わりに、override が発動されるたびに `OverrideEvent` を生成し、発動者・理由・回避された制約名を記録し、週次レポートで上位に自動送付する。override を禁止するフローは地下化する。目録化するフローは透明化する。これは検閲と公開の違いであり、2.1 の「残余を捨てるか保存するか」の統治版である。

```python
# silence_period.py — 沈黙の猶予期間の機械執行
# 哲学: 破壊的変更の前に「誰も異議を唱えない期間」を置く。
# 異議は発言だけでなく、参照・分岐・引用のすべてを含む。
# 沈黙の確認は「誰も見なかった」ではなく「誰も触れなかった」で判定する。
import time
from neo4j import GraphDatabase

DRIVER = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "pass"))
SILENCE_DAYS = {"L3": 90, "L2": 30, "L1": 7}

def touch_count(vocab_uri: str, since_iso: str) -> int:
    with DRIVER.session() as s:
        q = """
        // 猶予期間中の「接触」を数える:
        // 参照クエリ実行(AccessLog)、分岐(branch)作成、マッピング提案(L0-L2提出)。
        // 接触 = 誰かがこの語彙をまだ使っている、という証拠である。
        MATCH (a:AccessLog)
        WHERE a.target = $vocab AND a.at > datetime($since)
        RETURN count(a) AS touches
        """
        return s.run(q, vocab=vocab_uri, since=since_iso).single()["touches"]

def can_commit_l3(vocab_uri: str, proposed_at: str) -> bool:
    deadline = time.mktime(time.strptime(proposed_at, "%Y-%m-%d"))
    if time.time() < deadline:
        return False  # 猶予期間そのもの未完
    if touch_count(vocab_uri, proposed_at) > 0:
        return False  # 猶予期間中に接触があった = 沈黙が成立しなかった
    return True
# 「接触」の定義が判定の実質を決める。アクセスログの粒度は
# 組織が現場の活動をどこまで監視するか決定する——監視と保護の境界は
# この関数のコメントではなく、アクセスログのスキーマに書かれる(→1.6 NonRecordingRule)。
```

最後のコメントの重さを、本章の読者ならもう測れるはずだ。沈黙を機械的に検証するシステムは、沈黙を成立させるために接触を記録し続ける。記録しないことの設計（→1.6）と、沈黙を証明するために記録する設計（本節）は衝突する。衝突の解決は原理では下せず、`NonRecordingRule` の対象（個人レベルの閲覧痕跡）を猶予判定から除外する——すなわち「団結した接触」（共有ダッシュボードでの閲覧、分岐、提案）のみを証拠にする——という**政治的選択**としてのみ下される。設計者はこの選択を明文化し（`SilencePolicy.decider`）、2.6 の級 L2 変更として版数に載せる。倫理がコードになる瞬間とは、こういう局所的で小さく、しかし全員が生き残る賭金の場所に現れる。

### 誰が分類を書き換える権利を持つか — 本章の答え

問に戻って、本章の答えを条文形で置く。

1. 分類を書き換える権利は、その分類で**記述される人々**（現場）が最終的に保持する。マスター語彙の主権者は、彼らの代理であり、代理の権限は取消可能でなければならない（委員会メンバーの任期、`OverrideEvent` の上位可視化）。
2. 不可逆な変更（L3）は、影響を受ける現場代表の拒否権を必要とする。拒否権は棄却ではなく**延期**の権利である——L3 は委員会決議で90日追加延期できるが、無期限延期はできない（延期の無限反復は、暴力の先送りではなく暴力の隠蔽である）。
3. 承認されなかった主張も履歴に残る権利がある（不服従の三装置）。
4. 変更の権利は権限システムにのみ存在し、個人の技量には存在しない。push できない senior engineer より、push できる junior の提案が先に墓標を持てる。この不公平は意図的である——権利の所在をコードに置かないと、権利は実績と序列に移住する（知識政治の古典形）。
5. この四条文自身も L2 級の変更対象である。憲法の改正手続は憲法に書かれねばならず、それは本文のこの段落が履歴代数に載ることを意味する。

### 級の実装 — 変更級機械検査の完全コードと運用事故集

級体系（L0 発言・L1 候補・L2 実装・L3 制定、→前節）を、CI で動く機械検査として実装する。変更対象のファイルパスから級を導出し、級の要求（承認者・署名・落日）が commit message と graph の変更記録に揃っているかを検査する。

```python
# tools/change_grade_check.py — 級の実装(→2.5 ブリッジの直前に置く門)
GRADE_RULES = [
    (r"mappings/.*\.yaml$",        "L3"),   # 条約=分類制定(→6.1)
    (r"onto/tbox/.*\.ttl$",        "L3"),   # 正規系 TBox
    (r"onto/abox/.*\.ttl$",        "L2"),   # 記述内容(事実)
    (r"policies/.*\.rego$",        "L2"),   # 方針(→6.4)
    (r"docs/decisions/.*\.md$",    "L0"),   # 発言・記録(誰でも)
]
REQUIRED = {"L3": ["approval:", "signed-off-by:", "sunset:"],
            "L2": ["approval:", "sunset:"], "L1": ["thread:"], "L0": []}
def grade_of(path):     # 最も強い級が勝つ(多重マッチは L3 に解決)
    return max((g for p, g in GRADE_RULES if re.search(p, path)),
               key=lambda g: int(g[1]), default="L1")
def check(commit: str, changed: list[str]) -> list[str]:
    g = max((grade_of(f) for f in changed), key=lambda g: int(g[1]), default="L1")
    return [f"Lacking '{tag}' (grade {g})" for tag in REQUIRED[g]
            if not re.search(rf"^{tag}", commit, re.M)]
```

運用事故集を三件、級体系の運用史として inscribe しておく。**事故一：級 infl の静かなる上昇**——L3 承認の待ち時間（例 3 週間）に業が疲れたチームが、TBox 変更を「docs の要約」に書いて実体変更を abox（L2）に忍ばせる。検査の穴——abox/tbox 分離が実体で守られていない（TBox 相当の変更が abox ファイルに書かれる）。処方——級判定をパス名でなく**変更内容の構造解析**で二段目を持つ（`.ttl` の diff に class/property 定義があれば abox でも L3 に上げる——意味の変更の解析は→2.2 の差分演算の運用実装）。**事故二：署名の形式化**——`signed-off-by:` の列は埋まるが、承認者が変更の意味を検証していない（4.5 の read-then-approve、→8.5 の形式読解のコミット版）。処方——L3 承認に panel 参照を要求する（承認メッセージに CQ 検証結果・roundtrip 統計・落日統計の graph:// URI を最低1つ——**証拠を貼れない署名は署名ではない**、→4.4 の証拠条約）。**事故三：級のない紧急変更**——障害復旧の臨時変更が「紧急」で無級に走り、そのまま残る。処方——紧急変更は級0で通すが、`hotfix:` タグで**48 時以内の級づけ**を強制し、未精算の hotfix を scorecard に載せる（紧急は級外ではなく、級の猶予である——2.6 の沈黙の猶予の運用版）。

三事故の共通の教訓は、**級はファイルの属性ではなく、変更の語義の属性**だということである（パスを撃ち抜ける語義検査が第二段として必要——2.2 の「止揚は差分として計算できる」が、統治の機械検査としてここで回収される）。

### 級のミニ三例 — 同じ変更対不同の领域で級が変わる実演

級体系（→前掲）の最難所は「変更の級は変更の種類ではなく**載せる重み**で決まる」ことにある。同じ形の実体変更が別々の級に着地する三例で缔ぶ。

**例一**：`Equipment.vibrationRange` の upper を 4.2→4.5 に。引用 CQ なし・落日中の実測 E1（→4.1）—L1。理由：実証の帯の扩大が計器の告発阈値を上げる=安全側の余白を減らす、ただし落日周期 90 日内に effect_verification が戻る（→7.3）。**例二**：同じ数値変更、ただし夜間無人セクションの停止规則（→5.5 ステートマシン guard）がこの upper を読む—L3。理由：末端（5.1）が夜間審議者の落日周期に依頼する系で、閾値変更は末端の時間設計の変更になる（→7.6 段2 の落日=末端の巡回、閾値は末端の知覚能力、→感知能力の変更=統治変更）。**例三**：同じ数値変更、site 側の語彙 `strong-shake` の閾値としても二重使用されている（条約なしの暗黙の二重定義—→6.1 の摩擦統計が発見済み)—L3 加条約贸易。理由：分類の二重使用下での変更は一方の現場の語の世界を無声で変える（→6.3 不可視损失の静態形）。

三例の教学を一文に置く。級は diff の文字ではなく diff の**辺の集合**（CQ・guard・条約・落日）で決まり、ゆえに級自動計算（→前掲の change_grade_check）は diff ではなく**グラフの閉包**を計算する（変更対象から 2 次周辺の依頼ノード数と種別が級の輸入——2.4 の「分類の暴力」が局所ではなく網目で起きることを、級計算が機械的に示す）。

### 実行練習

1. `change_class.rego` に自分の組織の直近の変更10件を通し、機械級分けと人間級分けのズレを調べよ。ズレが発生した変更の「交渉史」（誰が L1 に下げたがったか）を記録し、交渉の方向が不可逆性と無関係な序列の関数であることを例証せよ。
2. `silence_period.py` の `touch_count` に対する L0〜L2 提出を自分で作り、猶予期間が「延長された」事例を1つ作れ。延長を承認するのは誰か、その承認の級はいくつか、条約の条文（上記1〜4）を引用して決めよ。
3. 自分の組織に `RejectedProposal` 墓標を1か月運用し、墓標の数と棄却理由の質を測れ。「再提案が棄却理由の更新なしに提出された」割合は、組織の学習率の代理指標である。第4章の competency questions に対し、この墓標一覧が「現場が問いたかったが潰された問い」の供給源になることを、5行で論じよ（→4.2・2.6 の接続）。
