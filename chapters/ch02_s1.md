## 2.1 分節化の暴力 — 分類が得るものと奪うもの

第1章で、明示化（explicitation）は原理的に完全になりえないことを見た。本節は一段荒い刃を扱う。知識を明示するとは、世界をまとまりに「切る」ことである。切る行為は、得られるものと捨てられるものを同時に決定する。カテゴリー（category）という語には、切るという語層が刻まれている。その語感は消えたが、行為は残っている。「これは `Misprint` である」と確定する瞬間、我々は依然として世界に刃を入れている。本節ではこの切断を分節化（articulation / sectioning）と呼び、暴力を比喩としてでなく計測可能で設計可能な対象として扱う。分類が得るのは数えられること・比較できること・部門間で転送できることだ。奪われるのは粒度、含み、その場限りの指示、そして報告そのものを発火させていた行為性である。同じスキーマでも、この差を記録する設計と記録しない設計では、保存装置にも埋葬装置にもなる。残余（residue）を捨てるか保存するかが設計を分ける——これが本節の中心命題であり、第2章全体の地盤になる（→第2.2節、→第2.5節）。

### 2.1.1 分類は刃である — caedo から category まで

語源を三層、そのまま引いておく。第一層は物理的な切断である。印欧語根 \*(s)keh₁- は「切る」で、ラテン語 caedere（叩いて切る）と secāre（切り分ける）に分かれた。caedere からは caesura（韻節の切れ目）、caesiem（切り傷）、homicide が出た。secāre からは sectio（切断）→ section、segmentum（切り痕）→ segment、以及び secans（切っている者）→ secant が出た。第二層は言語的な切断である。ギリシア語 katēgorein（καταγορεύειν）は ἀγορά（広場）で何かを「言い放つ」「～だと申し立てる」の意で、新約聖書では「告発する」に近づいた。ラテン語 translators はこれを categoria と写し、アリストテレスの十範疇（categories）の翻訳語にした。第三層が本書の着眼点である。つまりカテゴリという語には、(1) 切る（世界を分ける）と (2) 告発する（他を排除して名指す）という二重の暴力が、語の層として刻まれている。

この語源は飾りではない。カテゴリが中立な記述ではなく、つね誰かの申し立てであったことを思い出す装置になる。アリストテレスの十範疇は、世界の部位の列挙ではなく、「ものについて言いうる位（πότερον λέγεται）」の列挙だった。存在論であると同時に構文である。これはそのまま現代の設計文書に翻訳できる。スキーマは存在論の主張であり、API と列挙型はその構文上の断定である。`defect_type` の値域を 12 個の列挙値に閉じたとする。その瞬間、コードは「この領域にはこの 12 種以外の異常は存在しない」と申し立てている。世界が閉じたかどうかは、コードの正しさとは無関係である。

```python
# 哲学的意図: enum は katēgoria（申し立て）である。
# 閉じた瞬間に「他は存在しない」という存在論的断定が、型宣言の形でコードへ混入する。
from typing import Literal, TypedDict

DefectType = Literal[
    "PaperJam", "Misprint", "Tension", "Coating",
    "Crease", "Splice", "Static", "Calender",
    "RollEdge", "Humidity", "Operator", "MISC",
]  # MISC は世界の型ではなく、我々の無知の別名である（→2.1.2 の残余論）


class ClosedRecord(TypedDict):
    defect: str
    type: DefectType


def record_closed(defect: str, t: DefectType) -> ClosedRecord:
    # closed-world assumption: 列挙にない語はこの時点で受け付けられず、
    # 現場の言葉はログにも残らない。失われたものは復元クエリの対象にすらならない。
    return {"defect": defect, "type": t}


def record_open(defect: str, raw_term: str, t: DefectType | None) -> dict:
    # open-world: 現場の語（raw_term）を一次データとして保持する。
    # 切断は行う。ただし切断の両側を保存する。この 2 行の差が第2章の全設計差である。
    return {"defect": defect, "type": t, "raw_term": raw_term,
            "cut_performed": t is not None}
```

`record_closed` と `record_open` の差は、処理能力の差ではない。保存される世界の量の差である。しかもこの差は後から回復できない。切断された側は、切断が行われたこと自体が記録されていない限り、痕跡を残さない。

現場の失敗例を一つ、実際の数値の形で書いておく。ある紙加工ラインの品質システムに 12 値の `defect_type` を導入した。導入当初は欠損値率 3% で、ダッシュボードは健全に見えた。4 年後、`MISC` への流入は全件中 38% に達していた。`MISC` の内部では現場独自に 6 種の呼び名が自然発生していたが、列挙型にその型がないため集計も照会もできない。真の障害の増大（カレンダーロールの面圧異常、8 か月間で 3 件）が `MISC` の文字列メモに混じって検出されず、最終的にライン停止事故になった。原因は作業者の怠慢ではない。列挙は成功していた。失敗したのは、列挙の外部で分類が自律的に発生していることを観測しないデータモデルである。

### 2.1.2 切断は必ず残余を生む — 残余の三型

分類が残余を生むのは偶発ではない。残余は分節化の構造的不分払いである。理由を三つ挙げる。第一に、語彙は有限で世界は有限でない（列挙は必ず余る）。第二に、切断は一度で終わらず、部門ごとに別々の刃が入る（同じ領域に複数の分類が重なる）。第三に、世界には切る以前の状態がある（連続量・傾向・関係・手応え）。

残余には三つの型があり、それぞれ症状と対処が違う。混同すると設計を誤る。

| 型 | 定義 | 現場の言葉 | コードの症状 | 保存の形 |
|---|---|---|---|---|
| 未分類（unclassified） | 世界の切断が語彙の網の外にあった | 「あれは MISC に入れてます」 | `OTHER`/`MISC` への流入率上昇、自由記述の増長 | `Residue` ノード + レビューキュー |
| 多重帰属（cross-classification） | 二つ以上の切断が同時に成り立つ（階層の交差） | 「あれは紙切れじゃなくて張り付けのどっちでもいい」 | `disjointWith` 違反、多重分類の強制で報告が減る | 多値関係（`classifiedAs*`）を正規化せず許可 |
| 非分節（unarticulable） | 切る以前の状態。連続・傾向・関係・評価 | 「機嫌が悪い」「そろそろ来る感じ」 | 観測値はあるが型がない、閾値設計の論拠が消える | 生テレメトリと原文を保存し、型づけない（→第1.4節） |

第三の型が最も高価だが、最も扱われない。非分節なものは、保存するのではなく「型づけないまま残す」しかない。ここで重要なのは、残余は計測できるという点である。残余の総量は測れない（測れないことの測れない部分がある）。しかし残余の痕跡——`OTHER` 流入率、自由記述の字数、分類時の逡巡——は統計として記録できる。

```python
# residue.py
# 哲学的意図: 残余を「データの質の低さ」としてではなく、
# 語彙の世界に対する不足の計測値として扱う。数値は将来の分類のための証拠になる。
from dataclasses import dataclass

UNRESOLVED = {"MISC", "OTHER", "UNKNOWN", ""}


@dataclass
class Ticket:
    raw_term: str          # 現場が実際に言った語（原文は絶対に変更しない）
    master_type: str       # 正規化後の語（1対1とは限らない）
    free_text_len: int = 0 # 自由記述に逃げた字数 = 語彙が食いきれなかった量


def residue_rate(tickets: list[Ticket]) -> float:
    cut = [t for t in tickets if t.master_type not in UNRESOLVED]
    if not tickets:
        return 0.0
    return 1.0 - len(cut) / len(tickets)


def leakage_index(tickets: list[Ticket]) -> float:
    # 正規化はされたが、現場語とマスター語の距離が大きいケース。
    # 「分類は通ったが意味がすり減った」領域を数値化する（→2.1.3）。
    scored = [t for t in tickets if t.master_type not in UNRESOLVED and t.raw_term]
    if not scored:
        return 0.0
    return sum(t.free_text_len for t in scored) / len(scored)


if __name__ == "__main__":
    data = [Ticket("紙の機嫌が悪い", "MISC", 42), Ticket("カス残り", "Splice", 3),
            Ticket("巻きの癖", "Crease", 27), Ticket("張り付け", "OTHER", 55)]
    print(round(residue_rate(data), 3), round(leakage_index(data), 1))
```

この 2 つの数値を運用に乗せると、ダッシュボードの読み方が反転する。`MISC` の増加は現場の無関心ではなく、語彙の世界への不足として読める。`leakage_index` の高さは、その分類が意味をどれだけ削って通したかのおおよその目安になる。どちらも暗黙知の総量を測るものではない。あくまで明示化の試行の履歴から事後に推定した痕跡の数値である。この留保を忘れた瞬間、残余率は「残余の少なさ」を競う指標に堕落する（Goodhart の法則、→第1.1節）。

### 2.1.3 正規化という摩擦 — マスター用語への翻訳で何が減るか

企業システムで暴力が最も無自覚に行使される地点が正規化（normalization）である。マスターデータ管理（MDM）、統制語彙（controlled vocabulary）、マスター項（master term）。現場が 11 通りの言い方をする異常を、設計側が 8 個のマスター用語へ写す。写像はレビュー済みで、用語辞書に登録され、承認フローを通っている。それでも意味はすり減る（semantic wear）。減り方には四つの型がある。

| 失われ方 | 何が失われるか | 現場の例 | 翻訳後の状態 | 復元のための設計 |
|---|---|---|---|---|
| 粒度の潰れ（granularity collapse） | 現場が区別していた 2 以上の状態 | 「表面のよれ」と「裏面のよれ」 | `Crease` 一種に潰れる | `narrowerMatch` を保持し、上位語から下位語へ展開可能に |
| 含みの除去（connotation stripping） | 評価・緊急度・責任の所在 | 「そろそろ来る感じの張り付け」 | `Splice`（緊急性の標識が消える） | 原文 + 感情価・緊急性を別属性で保存（→第1.4節） |
| 指示詞の断切り（indexicality loss） | 状況依存の参照 | 「さっきのあれ」 | `null` または誤った既定値 | 観測時刻・区域・作業文脈を関係ごと保持 |
| 行為性の消滅（loss of action-implication） | 語を使うことが行動を発火させていた事実 | 「これは `RollEdge` だ」と言うことで停止が決まった | 記述としての型になり、行動が消える | 記述ではなく `Action` を語に紐づける（→第7.3節） |

失敗例を、報告件数の形で書く。あるグループ会社が 3 部門の用語を統一する「単一語彙化計画」を行った。現場の 47 語を 19 のマスター語へ写し、マッピング表は各部門の品質管理者が承認した。6 か月後、異常報告の件数が 1,400 件/月から 430 件/月へ落ちた。失われたのは情報ではなく、報告という行為だった。分析すると原因は三つ重なっていた。現場語には報告者の評価が含まれていた（「これは危ない方の癖だ」）。マスター語は観測者のための語で、行為者のための語ではなかった（含みの除去）。そしてマスター語で報告すると、自分の名前が履歴に残り、評価を含めない文章になったため、報告が処罰のリスクに変わった（権力の層、→第2.6節）。用語を統一すると報告が減る、という現象は組織の抵抗ではなく、翻訳が行為の条件を変えた結果である。

意味のすり減りは完全に測れない。しかし片方だけ測れる。往復翻訳（round-trip translation）である。マスター語から現場語へ逆翻訳し、元の現場語に戻るかを見る。戻らなければ、その語の contents がマスター語に保存されていないことになる。

```python
# 哲学的意図: 翻訳の損失を「意見」ではなく「戻れないケースの数」として記録する。
# 戻れない語の集合は、その語彙が持っていない意味の目録である。
GLOSS = {
    "Crease":   {"表面のよれ", "巻きの癖", "シワ"},
    "Splice":   {"張り付け", "継ぎ", " splice 残り"},
    "PaperJam": {"詰まり", "紙詰まり"},
    "Tension":  {"テンション異常"},
}
FIELD_VOCAB = {"表面のよれ": "Crease", "巻きの癖": "Crease",
               "紙の機嫌": None, "よれ": "Crease"}


def wear_report() -> dict[str, list[str]]:
    exact, narrow, orphan = [], [], []
    for field_term, mapped in FIELD_VOCAB.items():
        if mapped is None:
            orphan.append(field_term)                 # 網の外 = 残余（→2.1.2）
        elif field_term in GLOSS.get(mapped, set()):
            exact.append(field_term)                  # 往復で戻った = 意味が保存された
        else:
            narrow.append(field_term)                 # 片道のみ = 意味が削れた
    return {"round_trip_ok": exact, "one_way_only": narrow, "unmapped": orphan}


if __name__ == "__main__":
    r = wear_report()
    total = sum(len(v) for v in r.values())
    print(len(r["one_way_only"]) / total, r)
```

`one_way_only` に入った語は、そのマッピングが捨てた意味の目録である。「よれ」は `Crease` に渡るが、`Crease` の定義（ gloss）には「よれ」が戻らない。つまり `Crease` を見ても「よれ」の区別は復元できない。これは主観的な感想ではない。 gloss を設計者が書いたという事実だけが前提の、検証可能な主張である。

### 2.1.4 暴力は除去できない — 減らせるのは可視性だけ

ここで本書の立場を明確にしておく。分節化の暴力は除去できない。理由は三つある。第一に、保存は有限の語彙を要する。無限の語彙は保存ではなく複製であり、転送できない。第二に、比較は切断を要する。切断されていないものは集計できない。第三に、分類する主体は切断の外部にいない。スキーマを書く者は、自分の暗黙知で刃の入れ方を決め、その決め方を明示できない（→第1.6節、→第5.2節の被投性）。

したがって設計目標は「暴力のない分類」ではなく、暴力の総量と分布を可視化されたものに変えることだ。三つの原則になる。

1. 記録の原則：切断を最新版の状態としてでなく、イベントの履歴として保存する。どちらの刃が入り、誰が入れたかを残す（→第2.5節）。
2. 可逆の原則：削除を持たない。廃止は `deprecated` と `retires` の関係で表し、失われた語は履歴から辿れるようにする（→第2.4節、→第2.6節）。
3. 可視の原則：残余と翻訳損失を品質コストとして運用画面に出す。見えない損失は予算化されず、予算化されないものは必ず膨張する。

無自覚な分類と自覚した分類の差を、運用観測点で並べる。

| 観測点 | 無自覚な分類 | 暴力を自覚した分類 |
|---|---|---|
| `MISC`/`OTHER` | 現場の怠慢。クレンジングで消す | 語彙不足の指標。レビューキューに積む |
| 語彙変更 | マスターを UPDATE する | 変更をコミットとして記録（誰が・なぜ・何が減ったか） |
| 二語の競合 | 片方を正とし他方を削除 | `closeMatch` を保持し、裁定を履歴に残す |
| 現場の報告低下 | 「周知が足りない」と訓練を増やす | 翻訳コストの現れと読み、現場語を戻す |
| 監査 | 現在の値のみ | 主張と、その変更への主張まで（→第2.5節） |
| 破壊的変更 | 即時反映 | 沈黙の猶予期間と不服従の経路（→第2.6節） |

### 2.1.5 では工学的に何をするのか — 五つの実装判断

思想を配線に落とす。この節の結論は次の五つの判断として実装される。

**判断 1：現場語を一次データとして保存する。** 正規化後の値だけを持つテーブルは、切断の片側しか保存しない。`raw_term` を必須列とし、原文は絶対に後処理で書き換えない。書き換えは意味の抹消であり、抹消を抹消する方法はない。

**判断 2：現場語とマスター語の対応は関数ではなく関係である。** 1 対 1 を前提した外部キーは、暗黙の `exactMatch` 宣言になる。対応は `skos:exactMatch` / `closeMatch` / `broadMatch` / `narrowMatch` の位相付き関係として保持する。`owl:sameAs` は使用禁止とする（置換可能性は意味の同一性ではなく、同一性の申し立てである）。

```turtle
# vocab.ttl — 哲学的意図: マッピングは「翻訳の解像度」そのものを値として持つ。
# exactMatch はほぼ常に過剰な断定である。closeMatch を既定にすると、
# 失われた意味が関係の型として可視に残る（→第2.4節で制約として実装する）。
@prefix skos:  <http://www.w3.org/2004/02/skos/core#> .
@prefix ex:    <http://example.com/plant#> .

ex:Crease a skos:Concept ;
    skos:prefLabel "折れ目" ;
    skos:definition "紙の線状の変形で、折り工程の下流で発生するもの" .

ex:field_yokire a skos:Concept ;
    skos:prefLabel "よれ"@ja ;
    skos:closeMatch ex:Crease .            # 往復で戻らない = 意味のすり減りが宣言されている

ex:field_makinosyuku a skos:Concept ;
    skos:prefLabel "巻きの癖"@ja ;
    skos:broaderMatch ex:Crease .          # 現場語の方が細かい。粒度の潰れを明示

ex:field_kigen a skos:Concept ;
    skos:prefLabel "紙の機嫌"@ja .         # 意図的未マッピング。残余として保存（→判断 3）
```

**判断 3：残余をノードにする。** `MISC` を値として置くのではなく、未解決の語を `Residue` ノードとして立て、レビューキューに積む。レビューは「正しい分類を決める」場ではなく、語彙が世界のどこに負けているかを読む場である。

```cypher
// residue.cypher — 哲学的意図: 残余を「その他」というゴミ箱にせず、
// 将来の分類の証拠としてグラフの一等市民にする（→第2.5節で履歴化する）。
CREATE CONSTRAINT residue_key IF NOT EXISTS
FOR (r:Residue) REQUIRE r.key IS UNIQUE;

MATCH (t:Ticket {master_type: 'MISC'})
WHERE t.raw_term IS NOT NULL
MERGE (r:Residue {key: 'misc:' + t.raw_term})
  ON CREATE SET r.first_seen = t.ts, r.seen_count = 1,
                r.status = 'unresolved',   // 解決済みかどうかが、語彙の負けた場所の地図になる
                r.example = t.raw_term
  ON MATCH  SET r.seen_count = r.seen_count + 1, r.last_seen = t.ts
MERGE (t)-[:LEFT_RESIDUE]->(r);

// 語彙の負荷点のランキング: 頻度 × 未解決。上位語は新規コンセプトの候補である。
MATCH (r:Residue) WHERE r.status = 'unresolved'
RETURN r.example, r.seen_count, r.first_seen, r.last_seen
ORDER BY r.seen_count DESC LIMIT 10;
```

**判断 4：正規化イベントをコミットとして記録する。** 「`yokire` が `Crease` に統合された」は状態ではなく出来事である。変更者・意図・差分・失われた区別を、差分として保存する。これは第2.5節の Git 的コミットモデルの予告である。

**判断 5：意味損失をスロットルに接続する。** 破壊的マッピング（2 語の統合、値域の縮小）を承認する前に、`wear_report()` の `one_way_only` と影響件数を提示し、猶予期間を置く。損失が見える場所に置かれていない設計では、損失は必ず無制限になる。

実装の分岐を三つ示す。本書の採用は C だが、A が選ばれているプロジェクトが多数派であるという事実も記しておく。

| 分岐 | 仕組み | 利点 | 破綻モード | 本書 |
|---|---|---|---|---|
| A 正規化先行 | 入力時に必ずマスター語へ写す | 集計が速い、実装が単純 | 意味の抹消が監査ログに残らず、報告行動が消える | 却下 |
| B 事後正規化 | 原文保存、分析時にバッチで写す | 原文が残る、柔軟 | マスター語が後から決まるので運用が待てない | 部分的採用 |
| C 原文保存＋遅延バインディング | 原文と暫定写像を同時に保存し、写像を修正可能な関係として持つ | 切断が履歴化され、翻訳損失を測れる | 写像の一貫性管理コストが高い | 採用（→第2.4節・→第6.3節） |

### 2.1.6 この節のアポリア

三つの難点を残す。第一に、残余を保存する設計も、再び分節化する。`Residue` ノードは未分類を救うが、やがて `Residue` 自身が分類され、`status` と `type` を持たされ、新しい残余を生む。残余の再分節化は無限後退する。この後退は打ち切れるものではなく、レビュー周期という運用で切るしかない。第二に、意味のすり減りの測定は、測定可能な分しか測っていない。「報告しなくなった人」はログに残らない。失われた反事実（報告されていたはずの 1,000 件）を我々は復元できない。だから wear 指標は損失の総量ではなく、損失の下限である。第三に、どの切断を正当とするかの裁定は、システム内部では決定できない。裁定は人間の討議に委ねられる（→第6.2節のハーバーマス）し、その討議の条件をシステムが形作ってしまう。この循環は解けない。解けないものを前提として設計に織り込む方法が、次節以降の主題になる。

次節では、この切断をヘーゲルの止揚（Aufheben）として読み替え、破棄しない変更の差分設計へ転用する（→第2.2節）。
