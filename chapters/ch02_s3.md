## 2.3 スティグレール — 第三次保持と記憶の外部化

2.1で分類の暴力を、2.2でその暴力を履歴として引き受ける演算（止揚）を見た。しかし暴力を引き受けるには、失われたものが「どこかに残っている」だけでは足りない。失われたものが、いまここにある認知そのものを組み替えていることを理解しなければならない。ベルナール・スティグレール（Bernard Stiegler）の記憶論は、その組み替えの理論である。彼の中心的な主張——技術的記憶（第三次保持）は、生物の記憶の外にあるのではなく、生物の記憶の内部に最初から入り込んでいる——は、オントロジーを「データベース」ではなく「記憶の臓器」として設計せよという、この本全体の中で最も急進的な設計命令に転化する。急進的であるが、実行可能である。この節の終わりには、あなたのオントロジーが既に人間の記憶を書き換えていることを示すクエリが手元にある。

### 三つの保持 — フッサールからスティグレールへ

スティグレールの道具立てはフッサールの時間意識の分析から始まる。音の例で理解するのが最速である。メロディを聴いているとき、いま鳴った音は既に消えているのに、私たちはメロディとして聴いている。消えた音が保持（retention）され、次の音が予持（protention）されているからである。スティグレールはこの時間構造に三層の区別を入れる。

**第一次保持（primary retention）**：いまの知覚そのものに内在する保持。消えゆく音が保持として耳に残っている層。誰も外部化できない。録音しても、録音されたのは第一次保持ではなく、第一次保持が去った後の代物である。

**第二次保持（secondary retention）**：回想・想起。第一次保持が沈殿し、回憶として呼び出せるようになった層。個人の記憶。ここまでは古典的な記憶論の領域である。

**第三次保持（tertiary retention）**：技術的保持。書物、録音、写真、データベース、そしてオントロジー。過去を物質媒体に外部化し、生物の記憶の寿命を超えて保存する層。

重要な点は、三層が「内→外」と整然と並ぶのではなく、**循環している**ことである。スティグレールはプラトン『パイドロス』の文字批判を引用してこれを示す。エジプトの神トートは文字を発明し、ファラオはそれを「記憶の薬（pharmakon）」として拒絶する。薬は毒でもある。文字が外部化された記憶は、想起の筋道を外部に依存させ、内部の想起力を痩せさせる。記憶を「強くする」技術が、記憶の在り処を人間から技術へ移す——スティグレールはこれを**弁証法的外部化（dialectical externalization）**と呼ぶ。外部化された記憶は、外にあるまま、内を再編成する。

第一次保持に第三次保持が先行している、というスティグレールの逆転も重要である。私たちは聴く前にすでに、聴き方を学んだ音楽の記録（第三次保持）を通じて聴いている。子どもが母語を「内側から」獲得できるように見えるのは、外部化された音と文法の系（第三者が記録し蓄積した系）が先に開かれていたからだ。記憶の外側は、記憶の内側の条件である。この逆転を認めるなら、オントロジーを「システムの部品」扱いする設計観は破綻する。オントロジーは、そのオントロジーを使う認知の条件である。

### オントロジーは第三次保持の工業化である

本書の定義をここで確定する。**オントロジーとは、第三次保持の工業化である。** 工業化という言葉には二重の意味を込めた。第一に量的拡大——書物が印刷されたように、記憶の外部化が複製・検索・照合の機械によって大規模化される。第二に工業固有の性格——分業、標準化、そして労働の知識への無自覚化である。

比較の表を作っておこう。個人レベルの第三次保持と、工業化された第三次保持の違いは、正確にそのまま設計要求の違いになる。

| 次元 | 個人の第三次保持（メモ・日記） | 工業化された第三次保持（オントロジー） | 生じる設計問題 |
|---|---|---|---|
| 書き手＝読み手 | 同一。意味のすり替えが起きにくい | 分離。他人（や機械）が読む | 意味の保証主体の所在（→2.6） |
| 標準 | 個別語彙で許される | 共有語彙を要求される | 分節化の暴力（→2.1） |
| 検索 | 脈略的手がかりで到達 | クエリで到達 | 語彙外の意味は到達不能化 |
| 改竄・劣化 | 自分による自然な再解釈 | 自分によらない変更・減耗 | 版管理と履歴（→2.4・2.5） |
| 忘却 | 自然な忘却が意味を浄化する | 忘却が発生しない＝消えない | 保存の過剰による硬直 |

最終行に注目してほしい。工業化された記憶は忘却しない。忘却しない記憶は、世界が変わっても昔の分類で世界を切り続ける。分類の硬直は、分類の暴力が時間軸で発火した形である。ゆえに第三次保持の工業化は、忘却の装置——削除ではなく退位させる装置（`deprecated`、→2.4）——を同格に設計しなければならない。忘却を設計できない記憶は、過去による統治を機械化する。

### 保持の工業化が認知を書き込む — 現場での観察可能な効果

スティグレールの理論を「深い話」で終わらせないために、グラフで観測可能な予測に変換する。第三次保持が第二次保持を書き込む最も実直な経路は、**記録が証言を汚染する**ことである。現場技術者の障害時の証言が、障害後に書かれた記録の語彙で語られるようになる——「あれは『ドリフト』と呼ばれていた件だよね」という呼びかけが、当事者の記憶そのものを『ドリフト』の枠組みへ寄せる。

これは測定できる。ある語彙（例: `Drift` ラベル）がグラフに導入される前後で、同じ作業者の障害説明の語彙分布が収束していくなら、第三次保持→第二次保持の書き込みが起きた証拠になる。

```cypher
// 「語彙の植民」クエリ: Drift ラベル導入前(3/1)と導入後(6/1)の
// 障害説明(IncidentNote)に現れた語彙の多様度を比較する。
// 多様度の低下＝説明が外部記憶の語彙に収束しつつある＝保持が認知を書き込んでいる印。
UNWIND ['2026-03-01', '2026-06-01'] AS cutoff
MATCH (n:IncidentNote)
WHERE n.recorded_at < datetime(cutoff + 'T00:00:00Z')
  AND n.author_id = 'P-114'
WITH cutoff, collect(DISTINCT n.phrase) AS phrases, count(n) AS notes
RETURN cutoff,
       size(phrases) AS distinct_phrases,          // 語彙の豊かさ
       toFloat(size(phrases)) / notes AS diversity // ノートあたりの語彙多様度
ORDER BY cutoff;
```

`distinct_phrases` が有意に落ちるなら、その作業者の説明世界はグラフの語彙に入植されている。このクエリは告発のためではなく、**語彙の導入が記憶の再編成であることを可視化するため**のものである。新語彙を本番オントロジーに入れる前に、語彙が何を統一し何を消すかを預告する装置として使う（→2.6の沈黙の猶予期間はこの預告の実務形である）。

### 既定の保持 — 記憶の標準化が設計されている事実

スティグレール後半期の中心概念に「既定の保持（retention by default）」がある。何を憶え、何を忘れるかが、索引・ランキング・フィードによって、個人の外で先取りされている、という分析である。検索エンジンは「あなたがこの過去に出会う経路」を既定として用意し、その既定が共有記憶の形を造る。

 industrial化されたオントロジーも同じ機能を持つ——否、持つ**ほかない**。`Context` や `Situation` のスナップショットクエリ（→1.5）が「場について何を先に目にするか」を返すとき、その返り順と選択が既定の保持そのものである。設計者は既定の保持を、自覚的に設計するか、無自覚に既定されるかをえり選ぶだけである。

```python
# default_retention_audit.py — 「どの保持が既定として作動しているか」の監査
# 目的: オントロジーの上位表示・既定視される節点が、
#       (1) 人間に再検証されていない、(2) 少数の書き手に偏っている、
#       という二つの腐敗条件を測る。
from neo4j import GraphDatabase

driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "pass"))

AUDIT = """
MATCH (n)-[w:WITNESSED_BY]->(v:ViewerSession)
WHERE v.viewed_at > datetime() - duration('P30D')
WITH n, count(v) as views, n.created_at AS born,
     max(CASE WHEN n.last_reverified_at IS NOT NULL
              AND n.last_reverified_at > n.created_at THEN 1 ELSE 0 END) AS rechecked
OPTIONAL MATCH (n)<-[e:AUTHORED]-(a:Author)
WITH n, views, born, rechecked, count(DISTINCT a) AS author_count
WITH collect({id: n.uri, views: views,
              unverified: (rechecked = 0), single_author: (author_count <= 1)}) AS rows
UNWIND rows AS r
RETURN r.unverified AND r.single_author AS corrupt, count(*) AS n_nodes
ORDER BY corrupt DESC;
"""
# 「30日間に多数回閲覧された（＝既定の保持として作動している）」節点のうち、
# 人間による再検証が一度もなく、単独の書き手に依存するものの数を報告する。
# 既定の保持の腐敗——標準化された忘却の中心に、無検証の単独証言がある状態——は、
# 記憶インフラの炎症所見である。
```

この監査の設計思想を述べておく。再検証（`reverified`）の概念がなければ、オントロジーは「記録された瞬間に永遠の真実へ硬化する」物質になる。第三次保持の工業化には、第二次保持の循環——人間が憶え直し、書き直し、時に抛棄する循環——が接続されていなければならない。記録と想起の循環が切れた工業記憶は、スティグレールの語でいえば毒（毒としての薬）が薬の顔を続けている状態である。

### 薬の判断 — 保持を絶つ設計

では、循環を接続する設計原則を三つ確定する。**第一に来歴（provenance）原則**：すべての第三次保持節点は、誰が・いつ・どの観測や発話から作ったかを辺として持つ（1.5節の `origin`・`AUTHORED` はその布石である）。来歴のない保持は、誰にも返答を要求できない幽霊である。**第二に再検証期限原則**：既定の保持として作動する節点には、保持寿命を設定し、期限を過ぎたら「再検証待ち」の格に落とす。保持の忘却（→上の表）の実装である。**第三に可読な矛盾の保存原則**：矛盾する保持は統合してはいけない。統合は暴力の隠蔽であり、矛盾を並存させたまま提示することが、ハーバーマス的に言えば妥当性要求の空間を開く（→6.2）。`equivalentClass` を自動適用しない 2.4節の规則は、この原則の帰結である。

最後に、スティグレールが『技術と時間』で繰り返す逆説を、設計の言葉に翻訳して置いておく。**記憶を保存する技術は、記憶を保存する能力を人間から取り除く方向に働く。だから記憶インフラの設計とは、人間の想起能力を増幅する配管を、記憶の本体の周りに故意に這わせる設計にほかならない。** この配管の最終形が第8章の対話UIプロトコルであり、その節に至るまで、本章の差分トラッキング（次節）と沈黙の猶予期間（→2.6）は、増幅配管の仮設として機能する。

### 第三次保持の実地判定 — 「あなたの記憶はどちらに属するか」の問診表

スティグレールの第三次保持（→前掲：記憶の技術的_third retention——録画・台帳・検索が「私の」記憶の一部を担う状態）を、設計レビューで使える問診表に落とす。第三次保持自体は悪でも善でもない（→8.1 の技術の二面性）——問題は、それが**第二次保持（自分の記憶）と第一次保持（現在の経験）を育成しているか、代替しているか**である。判定の三問を置く。

**問一（入口）**：その第三次保持（台帳・検索・AI 要約）の内容は、いつ・誰の第一次保持（経験）から inscription されたか。 Inscription 者が不在で、 inscription 時刻が登記されていない台帳は、記憶の主体が空白の台帳である（→5.1 の JudgmentEvent の accountable_to 欠如の記憶版——主体の空白は、更新経路の空白に直結する）。**問二（使用中）**：使う人は、台帳の条目を**手がかりとして自分の記憶を再生**しているか、条目を**読み上げて終わりに**しているか。再生には回想法が要る（→8.5 の理由面板——read ではなく再生への招待）。読み上げの運用（台帳の文をそのまま実行に移す）が検出される場所では、第二次保持が休職している（→8.1 deskilling-meter の site_coinations 逓減の入口事件）。**問三（更新）**：条目を更新できる人は、その条目の**使用経験を持つ人**か。経験なき更新（運用の現場を知らない者が台帳を書く）は、記憶の寄生である——台帳が記憶の主体から離れ、主体が台帳に寄生する（third retention の逆転）。

```cypher
// third-retention-audit — 第三次保持の問診(月次)
MATCH (e:EpistemicEntry) WHERE e.usage_count > 0 AND e.at < datetime() - duration('P18M')
// 問一: inscription 主体と時刻の登記
OPTIONAL MATCH (e)-[:INSSCRIBED_BY]->(p:Person)
// 問三: 直近の更新者が使用経験(その条目が参照するスレッドへの参加)を持つか
OPTIONAL MATCH (e)-[:UPDATED_BY]->(u:Person)
OPTIONAL MATCH (u)-[:PARTICIPATED_IN]->(:Thread)-[:REFERS]->(e)
RETURN e.entry_id,
       CASE WHEN p IS NULL THEN 'Q1:主体空白' ELSE 'Q1:ok' END AS q1,
       CASE WHEN u IS NULL OR uIsParticipant IS NULL THEN 'Q3:経験なき更新' ELSE 'Q3:ok' END AS q3;
```

（`uIsParticipant` の所在判定は上記 OPTIONAL MATCH の成否で代用できる——正確な実装は練習1に委ね、本書では照会の**意図**を明記する：第三次保持の条目が「誰の記憶から来て、誰の経験で更新されているか」の二列を、すべてのナレッジベースが常に持てるようにする。**主体の二列を持たない KB は、記憶の外注であって記憶の代理ではない**——この区別が 8.1 の診断の運用形である。）

この問診を 2.5 の git→RDF ブリッジと接続して閉じる。コミット履歴は本来、 inscription の主体と時刻の最良の簿記である（Author/Committer/時刻が機械的に残る）——ブリッジが Author を EpistemicEntry の INSSCRIBED_BY に写るとき（→2.5 のブリッジ設計の含意）、git は第三次保持の問診表を無料で提供する。ただしコミット authorship と inscription の主体は一致しないことがある（コードを書いた者と、知識を選んだ者は違う——→2.4 の分類制定の級）。よってブリッジは author を**候補**として載せ、Co-Authored-By トレーラーと審議記録で主体を確定する（主体の簿記は機械の記録と人間の承認の共同作業である——5章の人間側の設計が、記憶の簿記で先に現れる）。

### 簿記されていない保持 — 「書かなかった」を台帳に載せる

第三保持の台帳（→前掲）は書かれたものだけ数える。しかし組織の記憶を本当に削るのは、書かれなかった決断・開かれなかった会議・配られなかった情報である。**簿記されていない保持の台帳**を一度だけ開く（永久に開くのではない——沈黙の全量台帳は不可能なので、**サンプル審計**で十分だ。→2.5 の簿記の伦理は「すべてを書け」ではなく「書かない选択を書け」である）。

```cypher
// silence-audit — 決着したのにDecision/RuleAdoptionを持たない討議 thread の抜き取り検査
MATCH (t:Thread {resolved:true}) WHERE t.closed_at > datetime() - duration('P1Q')
  AND NOT (t)-[:PRODUCED]->(:Decision) AND NOT (t)-[:PRODUCED]->(:RuleAdoption)
  AND size([(t)<-[:PARTICIPATED_IN]-(:Person)]) >= 3
RETURN t.thread_id, t.closed_at, count { (t)<-[:PARTICIPATED_IN]-(:Person) } AS heads
ORDER BY heads DESC LIMIT 10;   // 3人以上で決着したのに決着産物がない=書かれなかった決断の候補
```

この抜き取り検査で名前の挙がる thread の参加者に、審計は「なぜ書かなかったか」を質問する（3 人以上の決着が産物なしで閉じる場合、ほぼ必ず「書く人が決まっていなかった」か「書く价値がないと思われた」のどちらかで、**前者は席の欠落、後者は評价の欠落**——2.1 の「書く人が決まっている」が第三保持の物質条件である理由がここで逆側から立証される）。抜き取り結果是四半期に 1 度、第三保持台帳の蓋に貼る（書かれなかったものの件数——記憶の台帳が記憶できないものの件数、この二列が并んでいる台帳だけが誠実な記憶の健康诊断である）。

### 実行練習

1. 上の「語彙の植民」クエリを、自分のプロジェクトの用語導入時期で走らせよ。データが足りないなら、会議メモの日付順に新語彙の初出と旧語彙の消滅を manually にでも追跡せよ。「導入6か月後に現場から消えた語」のリストは、分類の暴力の目録である。
2. `default_retention_audit.py` の閾値（30日・閲覧数）を2段階に変えて、既定の保持の「圏境」がどう動くか見よ。圏境に入る節点数が倍増する条件は何か、語彙の粒度と関係があるか、考察せよ。
3. あなたのチームの用語集を1つ選び、その語が「再検証されていない単独証言」であることを上の監査が検出できるように、`AUTHORED` と `last_reverified_at` を逆算して埋めてみよ。その上で、その語を実際に再検証した会議を開き、`last_reverified_at` を更新せよ。更新の瞬間、あなたは第三次保持の循環に一単位分の電気を通したことになる。
